# Architecture decisions

## Product target and deployment reference are separate

- 用户于 2026-09-02 明确纠正：Better Agent 是对标 `ai.betteryeah.com` 的完整 Agent 应用，既有设计覆盖 Agent、工作流、知识库、数据库、工具集成、发布、运行与观测；不是文档站或数据库演示。
- `E:/project/ai/agent` 只作为服务器部署方式的参考，不用于替换本项目的产品定位、页面或功能范围。数据库、凭据与持久化数据保持独立。
- 代码尚缺前端、HTTP 服务或执行器时，归类为既定产品目标下的实施缺口，不再要求用户重新选择“文档站还是业务应用”。具体功能仍遵循既有设计、依赖与安全验收门。
- CI、PostgreSQL 健康、页面 HTTP 200 均不能单独代表完整应用交付；须分别核验页面、业务 API、真实运行、数据持久化与端到端用户流程。系统分区修改等运维权限仍单独处理。

## Executable admission gates are closed-world

- G1 前门以冻结 manifest 和 parsed CI schema 为事实源；“包含必需命令/文本”不足以准入。
- dirty source 只能物化到 content-addressed disposable checkout；不得 stash/reset/checkout 当前工作树。
- 本地机器证据与 host-attested acceptance 分层，Provider 不得自签 Receipt。

## Closure identity kernel

- G1-A1 identity primitives live in release-core and reuse closed domain schemas / canonical JSON. Agent and Flow will share this implementation; no runtime or network fallback is added to identity generation.
- `binding-path-lp-utf8/1` uses fixed typed tags and uint32be UTF-8 framing; `rn1` hashes the full JCS pin. Input is snapshotted without getters or Proxy traps; path bytes and per-compilation registry memory have separate absolute limits.
- Historical G0 admission is scoped to its recorded subject. A local environment outage does not itself revoke that admission or prevent pure kernel TDD; new source still needs fresh real database/full-gate evidence before completion or release.

## Capability policy kernel

- Separate permission ceilings from intrinsic resource demands. Intersect scopes only in allow-sets; a required scope, operation or endpoint cannot be removed to make a demand pass.
- Egress uses deployment-approved network policy pins, not Workspace-supplied IP/CIDR, proxy or DNS servers. Canonical host/path/method/redirect meet is pure compilation, not proof that runtime SSRF enforcement or deployment approval already happened.
- Canonical composition must satisfy its input budgets at the output boundary too. Two bounded host/path sets can multiply into an oversized result; reject before returning instead of producing a value the next meet cannot consume.
- Budget ceilings are independent caps. Simultaneous input/output token minima also need joint feasibility against the shared total cap; use bigint to avoid unsafe Number sums.

## Pinned dependency graph staging

- A verified manifest graph is an intermediate deterministic artifact, not a compiled capability closure or proof that a resource was authoritatively sealed. Source preimages, nested closure bodies, effective path policies and registry provenance must be verified before publisher/admission integration; never promote candidate `sealed` text to authority.
- Graph traversal must enforce the longest root-to-leaf path, not first-visit depth. Memoized shared subtrees retain their full height; exact full pins and version-cycle identity serve distinct purposes, especially when a root semantic seed differs from its eventual compiled hash.

## Executable source preimages

- Agent executable source and released Agent share fields and cross-reference refinements, but source rejects final compiled/closure hashes. A semantic seed, a closure-hash-bound compiled hash and authoritative registry provenance are three different facts; intermediate helpers must not unpause publication.
- Before applying explicitly documented metadata exclusions or set ordering, compare complete canonical input and parsed output. A schema parser silently dropping a business JSON key must fail closed, not collapse distinct source documents into one hash.
- Recursive tagged schema variants dispatch on their discriminator before parsing their body. Depth and byte budgets do not prevent exponential work caused by trial-union reparsing inside those budgets.

## Operation declaration evidence

- Operation source binds full input/output JSON to a versioned preimage and complete operation pin. Keep this distinct from schema meta-validation, provider/SQL/index implementation verification, target registry provenance and GateSpec authorization; none follows from a self-consistent digest.
- A concrete Binding may add approval or operation-key requirements but cannot remove intrinsic requirements. G1 database operation verification independently checks read-only mode, safe effect and the Binding config's own stronger key declaration. Skill Pack exposure must use exact sealed member routes, never the single-operation checker as a generic fallback.

## Typed leaf source boundaries

- Database read scope includes selected, predicate, ordering and additional-filter columns; membership/order are implicit information flows. User columns need the Binding allowlist, all reads need intrinsic read/output classification. Fixed tenant/principal guards are mandatory and cannot be replaced by user filters.
- Source adapters bind typed content to complete pins but do not attest referenced implementations, catalog ownership or registry seals. Their returned intrinsic artifact deliberately excludes Binding-added narrowing; the final path compiler must incorporate that narrowing separately.
- A successful bounded prepare must remain verifiable. Independently bound artifact and source operands when their combined size is not part of the declared artifact contract; test large legal round trips alongside input-fit/output-overflow rejection.

## Composite source declarations

- Exact nested operation alias/hash equality does not prove that the intermediate Binding covers the known operation's effect/key/approval floor. Check each declared layer, including requires_key having a key source; final path-policy and registry verification remain separate obligations.
- Strategy model narrowing compares every complete descriptor identity, not only provider or contract hash. Source sandbox deny-all declarations are immutable content, not proof of actual runtime isolation.

## Signed inert Instruction Skill sources

- Signed source and trusted signer configuration are separate inputs. Match Workspace, key, publisher, origin and resource scope; an internally consistent signature does not attest configuration provenance, current revocation or host reviewer authority.
- Canonical public SPKI DER does not ensure a valid signer point. Require canonical prime-subgroup nonidentity Ed25519 keys and explicit strict verification through the pinned cryptographic library; retain independent real-signature and degenerate-key regressions alongside isolated guard-order tests.
- Scripts remain opaque signed assets, never Tools or executable dependencies. Source IDs and context caps are not effective closure paths or runtime token clipping; compile and enforce those separately before application acceptance.

## Bounded Schema validation

- Pin schema dialect, engine/formats/options, reference semantics and limits in the hashed validation profile. With exactly one resource and unique anchors, dynamic references can lower to confirmed static locations; relaxing nested IDs or external refs invalidates that proof. Validate the original document first, transform only a worker copy and preserve simultaneous references/siblings/array indexes.
- Worker deadlines and heap limits improve responsiveness but are not an OS sandbox or process-wide memory ceiling. Keep the concurrency slot until actual exit, including termination rejection. Source validation evidence is a reproducible result, not provenance, compiled closure or host attestation.
- All explicit Schema-bearing fields in Agent, recursively nested Flow, all four leaf resources and Skill Pack are collected by typed structure, never by `_schema` name scanning. Batch compilation is capped at 8,194 schemas / 8 MiB and retains the same 5-second worker deadline as single validation; duplicate documents may share compilation but must retain separate canonical field-path evidence, chunked 1,024 entries per evidence array.

## Closure compiler intermediate boundaries

- Internal path-expansion helpers must not invent persistent schema versions, independent hashes or public artifacts that downstream code could mistake for closure authority. They consume verified/prepared artifacts and remain private until a complete verifier and architecture contract exist.
- Source-declared disabled Bindings are not final policy-unavailable paths. Preserve disabled entries in the canonical namespace, name source-level projections explicitly, and only populate final `disabled_binding_paths` after recursive policy compilation.
- Canonical path segments must include the namespace in which a local ID is unique. Flow `node_id` is graph-local, so its identity preimage includes `graph_id`; whole-document graph IDs are globally unique and the entry graph is the literal `root`. A persistent byte-profile may be reset only while repository evidence proves no publisher or storage consumer exists; afterwards, semantic changes require a new version.
- Compose producer and consumer limits explicitly. A 4,096-node Flow can require a root plus 4,096 path identities, so the private registry budget must cover the legal source maximum without weakening its retained-byte ceiling.
- A “closure-local” identity registry must register the complete namespace present in that compilation slice before expanding a selected dependency. Registering only the matching Binding can hide cross-kind collisions and undercount the root namespace; direct dependency adapters therefore retain every root Binding and attach nested paths only to exact full-pin matches.
- Skill Pack member paths include disabled and unexposed members because both remain dependency/cycle and source-identity facts. Keep explicit source-disabled paths separate from descendants disabled later by effective policy, and do not emit a runtime route until exposure identity, member operation, path and route hash are sealed together.
- Internal SubAgent path expansion may expose the target Agent's immediate Binding namespace only after exact full-pin matching and direct same-version cycle rejection; it must retain `subagent_target` before dependency-owned Binding segments and must not synthesize a nested closure seal. External A2A targets are terminal leaf paths and never acquire fictitious internal Bindings.
- A Skill Pack route hash binds exactly `{schema_version, pack_binding_path, exposed_operation_id, exposed_operation_contract_hash, member_binding_path, member_target, member_operation_contract_hash}` using canonical JSON SHA-256. Route preparation may preserve disabled source routes, but only later effective-policy and publisher/registry sealing can authorize runtime use.
- A direct dependency compiler slice becomes graph-bound only after recomputing the complete expected pinned graph, matching the requested root to the graph root by full pin, resolving both exact nodes and proving the directed root→dependency edge. Graph consistency does not prove registry provenance; the publishing transaction must supply the authoritative snapshot.
- Apply the graph-bound edge proof uniformly to Pack, Flow, internal Agent and external A2A direct slices. A required nested closure hash on Flow/internal Agent is retained evidence, not verified nested closure bytes; external A2A is terminal and must not gain a nested seal.
- Agent-root GateSpecs compile under the exact root resource node and omit Flow-only source path/node fields. This source projection preserves canonical protected operation hashes but is not closed authorization until every approval Binding resolves an exact same-closure gate with complete operation coverage.
- Flow human-gate specs compile only after the Flow source and recursive paths are independently prepared; each entry binds the exact Flow resource node, full graph-aware source path and local node ID. Duplicate gate IDs across one Flow fail closed because compiled gate identity is resource-node plus gate ID.
- An Agent Binding with approval required must resolve exactly one same-source `approval` GateSpec and every concrete operation contract hash must be in that gate's protected set. Required approval with no concrete operations is not closed; approval-none must reject any intrinsically approval-required operation rather than silently omitting gate evidence.
- Leaf operation collection must preserve the complete root Binding namespace but attach the verified concrete operation pin only to exact full-pin, kind-compatible Bindings. Sibling paths receive an explicit empty operation set; they must never inherit the currently processed dependency's operation by positional join.
- Skill Pack routes and Binding operation sets are distinct projections: aliases may produce multiple exact routes to one member operation, while the final Binding operation pin set deduplicates by contract hash. Never deduplicate routes by operation hash because that would erase exposed IDs and path identity.
- A supplied compiled closure is not trusted merely because it matches the Zod shape. Snapshot it under an explicit closure budget, require lossless closed parsing, recompute every available node/path identity, then recompute `closure_hash` over the entire artifact excluding only that root field. A nested Agent/Flow joins its registry dependency on workspace/kind/resource/version/binding mode plus the committed nested closure hash; its published contract hash is not required to equal the closure-local semantic seed hash.
- Every set-like top-level closure array must have one canonical order before hash acceptance: assembly pins by full pin key, Bindings by canonical path, gates by source-node/spec identity, resource nodes by node ID, edges by full endpoint/relation/path tuple, and disabled paths lexicographically. Hash self-consistency never excuses an alternate permutation or duplicate.
- Nested Agent operations may cross a SubAgent boundary only after the graph's direct edge and committed child closure are verified. Resolve each child operation set through its exact child-root canonical Binding path and full target, then copy it to the already-derived parent-prefixed path; a local Binding ID is never a cross-namespace join key by itself.
- Nested Flow operations use the exact child Flow-node path and its full ordered `(graph_id,node_id)` ancestry, not `node_id` alone. Before prefix projection, require equality among the prepared Flow dependency manifest, the graph node manifest hash, the closure root manifest hash and canonical closure assembly pins; the nested closure hash by itself is not source/graph assembly agreement.
- Parent Flow/SubAgent call operations and projected child operations are separate authority layers. Determine the complete mount set by target kind plus full target pin, require exactly one verified call declaration per mount, then attach it by the parent's canonical root Binding path; never update every same-ID projected entry.
- Apply source/graph/closure dependency-manifest and assembly-pin agreement to nested Agent as well as Flow. Exact child Binding paths prove local projection identity, but do not by themselves prove the graph retained every transitive Strategy, Skill, or capability dependency.
- A leaf root Binding entry is closed only when its target/config/source hash, dependency node, canonical path segments, operation pins, approval gate and optional async child policy are re-derived from prepared sources. Meet Workspace, root and exact path-keyed Binding ceilings before resolving the leaf's full intrinsic demand; if the resulting policy requires approval, same-source GateSpec coverage is mandatory. Typed ceilings are compiler facts, not registry or admission attestation.
- Whole-Agent leaf assembly must compare sets at both levels: every leaf root mount has one exact path ceiling, while every unique target pin has one source candidate and one direct graph edge. Multiple mounts may share that verified target, but duplicate source candidates, missing targets, unrelated candidates, transitive-only nodes or a graph root manifest differing from the prepared Agent manifest all fail closed. Verify the bounded graph once for the complete dependency batch; reparsing an 8 MiB graph per leaf multiplies the public work budget.
- A compiled Binding entry is a semantic boundary, not a loose transport object. Binding kind fixes config version and all non-Pack operation kinds; operation pins, dependency node IDs and Pack routes are canonical unique sets. The effective operation allow-set must exactly equal the compiled operation set, its side-effect ceiling must cover every operation, and effective approval must agree bidirectionally with compiled GateSpec evidence. Only Flow/SubAgent may carry async child policy hashes. Every compiled Pack operation must be reachable through at least one same-Pack-path route whose exposed and member contract hashes agree.
- Closure resource-node `intrinsic_policy` is always the closed `CapabilityRequirementExpressionV1` topology (`leaf`, ordered `sequence`, set-like `parallel`/`alternative`, bounded `repeat`, or `nested_call`); a leaf wraps `CapabilityRequirementsV1`, and `nested_call` carries a separately verified invocation requirement plus its child. Unordered children and every leaf/invocation demand must be canonical before closure hashing, while sequence order remains semantic. `{}`, a raw flat requirements object, and resource-specific ad-hoc JSON are invalid. A pinned-graph node is only a dependency commitment (`node_id`, pin, manifest hash, nested closure hash), not a closure resource node. Nested verification must consume that strict commitment and validate the independently typed nested closure; never add a fabricated empty intrinsic policy or node role to cross the boundary.
- An Agent/Flow dependency resource node derives its intrinsic requirements only from the exactly verified nested closure root. The graph commitment's version tuple, node ID, nested closure hash and dependency manifest must all join; after that join, copy the typed root intrinsic policy under the graph's published pin. Do not equate the registry contract hash with the nested semantic-seed hash, and do not accept a caller-supplied replacement policy.
- A Skill Pack leaf member entry is compiled in the parent Agent namespace, once per exact Pack mount/member path. Its source candidate set is exact by unique full pin, while policy ceilings are exact by mounted path; meet Workspace, root, Pack-mount and member ceilings before resolving the verified leaf demand. Disabled Pack/member or unrouted member paths remain unavailable without deleting the compiled evidence entry.
- Skill Pack graph provenance requires two typed parentage layers in the same recomputed snapshot: Agent root→Pack and Pack→leaf. Verify both source-derived dependency manifest hashes in addition to the edges; root→leaf membership is not a substitute, and an extra graph dependency is authority drift even when all expected edges remain.
- Nested Agent/Flow operation and child-call projections must carry the exact dependency resource node generated by the verified closure join, so downstream compilation consumes child-root typed requirements without a second caller-controlled policy source. Parent compilation must use the topology envelope rules: sequence sums consumables/maxes depth and concurrency; parallel sums consumables/concurrency but maxes depth/duration; alternative takes the least flat axis-aligned envelope while preserving the expression; repeat multiplies consumables only; nested call adds an explicit invocation demand and increments child depth. Copying child minima still omits parent invocation cost and is forbidden.
- Flow/SubAgent invocation source may declare only demand axes. Operation hash, side effect and approval come from the exact verified operation pin, and the resulting requirements attach only to the parent canonical path; a child entry that reuses the local Binding ID must not inherit them.
- Compile the full requirements envelope from the same canonical topology as numeric minima. Conjunctive nodes union required scopes but intersect credential/principal modes; alternatives union modes, while conflicting provider/audience aliases for one requirement ID always fail closed. A flat alternative credential envelope is conservative and never replaces branch correlation in the retained expression.
- A Flow/internal-Agent composite entry proves the path ceiling can carry both the parent invocation and child-root operations, then narrows the emitted parent allow-set back to the exact call operation. Child operations remain authorized only at child-prefixed entries; copying them onto the parent path creates an authority alias.
