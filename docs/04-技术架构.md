### 1.1 五平台研究后的 Agent 控制面

[Dify、Coze、Flowise、Stack AI、Gumloop 横向研究](./research/agent-platform-comparison-2026-08.md)不要求增加首版微服务，而是要求现有 API/worker/package 内保持六个逻辑控制面：

| 控制面 | 初始 owner | 硬边界 |
|---|---|---|
| Authoring | Studio + API control routes | Agent/Flow/Instruction Skill/Strategy/Experience 分别保存 Draft；草稿和 preview token 不进入公开运行。 |
| Release | API publisher + Postgres | 分别生成不可变 Release、dependency manifest/hash、封闭的 kind-specific config 和类型化 pin；`skill_pack` 只做发布期展开。G0/G1 禁止 runtime latest/floating binding。 |
| Deployment | API policy/deployment module | 判别式 Agent revision 固定 Agent+Experience Release，Flow revision 固定 Flow Version；两者分别固定 policy、入口、credential mappings 与 revoke epoch，不能混用凭据。stable active pointer 只在准入事务解析；promotion/rollback 不参与已接受 Run 的逐 Call 重验证。G0 仅 development/staging，production 由 Evaluation Gate 解锁。 |
| Resolution | `policy` + `agent-runtime` | `Release 上限 ∩ CompiledCapabilityClosure ∩ 同类型 Deployment/Admission Profile ∩ principal/source ACL ∩ credential grant ∩ budget` 生成不可变 ResolvedAgentPlan/FlowPlan；嵌套 Flow/Agent 的凭据、出网、数据分类、operation 和副作用上限只能收窄。 |
| Execution | `run-core` + worker + flow/agent executors | Postgres Run/Step/Call/ChildRun/Checkpoint/HumanGate/Outbox 是事实；Flow/Strategy 使用版本化可恢复 ABI，等待释放 Worker，resume 固定原 Plan 且幂等。 |
| Observe/Eval | `eval-svc` 逻辑边界 + outbox consumers | Trace/SSE/报表是投影；Evaluation Suite/Run 固定完整依赖并作为 promotion 证据，不授予生产权限。 |

Instruction Skill、Agent Strategy、Tool/MCP、Flow、Knowledge、Database 和 SubAgent 保持不同资源类型：Skill 只提供过程上下文，Strategy 控制推理循环，Tool 执行动作，Flow 表达显式图，SubAgent 产生受限子执行。任何“技能”UI 只能是这些资源的装配投影，不能成为万能 JSON 执行器。

Flowise 已进入 EOL，只保留其 Agentflow/HITL/Document Store 设计样本，不加入依赖、兼容或迁移目标；具体证据和版本见横向研究。

### 3.1 初始部署单元与依赖方向

| 逻辑边界 | 初始部署单元 | 允许的通信方式 |
|---|---|---|
| Studio | `apps/studio` | 仅调用 API；不直连数据库、模型、对象存储 |
| API / 控制面 | `apps/api` | 使用领域包；写入控制数据、run 与 outbox；不在请求线程执行长任务 |
| 异步执行面 | `apps/worker` | 消费 outbox/job，使用领域包；以 lease 和幂等键执行 |
| 解析与沙箱 | `apps/parser-py` / 隔离执行池 | 仅接受受控任务；没有工作空间主凭据；默认拒绝任意出网 |
| agent-runtime、flow-engine、kb-core、plugin-core、model-gateway、db-svc | 初始均为 package | 不得私自变为跨网络调用；满足规模或隔离证据后才可提取 |

`db-svc` 在拓扑中表示数据访问策略，不是首版独立进程；所有用户 SQL、RLS 与资源归属检查只能经 API/worker 的受控数据访问层完成。

## 4. 必须原样保留的关键约定

复刻时这些行为不能"优化"，否则与 BetterYeah 不等价。全部集中定义在 `packages/shared`。

| 约定 | 值 |
|---|---|
| 变量语法 | 普通配置字段为 `{{path.to.value}}`；逻辑分支为 `js-expression-v1` 裸表达式；Code 的 `main` 使用沙箱裸变量绑定。三者的精确定义以 [Flow IR v1 §4](./architecture/flow-ir-v1与运行时契约.md) 为准 |
| 节点变量名 | 节点名即变量名：`start.content`、`llm_1`、`{{database_1}}` |
| Webhook start | 变量名就是 `start`，第三方 payload 从它取 |
| 全局变量 | `betterAI.store.set/get` 生命周期覆盖整个 Flow 运行。兼容导入器可把旧写法 `{{betterAI.store.get("value")}}` 规范化为受限路径引用；运行时模板解释器不得执行函数调用 |
| SDK 命名空间 | `betterAI.agent / session / store`；**Python 仅支持 store，session 暂不可用** |
| session 能力 | `conversationId` / `sessionId` / `agentInput` / `metaData` / `setMetaData` / `initSessionData` / `addChatRecord` / `getChatRecord` |
| betteryeah SDK | 五模块 `llm` / `knowledge` / `database` / `plugin` / `subFlow`；统一返回 `ApiResponse<T>`（`code`/`success`/`message`/`data`/`now_time`/`usage.consume`） |
| knowledge 检索参数 | `hitStrategy`：`MIX` / `KEY` / `SEMANTICS`；`maxResultNum` 默认 3；`similarity` 默认 0.4；`rankingStrategy` |
| SQL 限制 | 必加 `LIMIT`，最多 500 行，未加触发智能拦截 |
| Code 节点 | 必须有 `main`；无 return 则输出 null；输出必须可序列化；JS 仅 CommonJS `require` |
| API 节点 | 超时 300 秒；重试次数可配 |
| 分段 | 超 500 字强制切分；建议每段 500 字 |
| 知识库分段区间 | 「每个段落在 200-1000 个字之内」 |
| 问答 xlsx | 表头在第 2 行；1 问 ≤5 答；问 ≤100 字；答 ≤1000 字；无合并单元格；图片须完整置于单元格内 |
| 近义词 | 实体词 1 个且 ≤20 字；近义词 ≤25 个且每个 ≤20 字；英文逗号分隔 |
| 视频知识 | ≤150MB、≤5 个 |
| 知识标签 | ≤9 个 |
| 批量调试 | ≤200 条；文件字段单次 ≤20 个 |
| 上传文件 | Agent 单次 ≤5 个文件或图片 |
| SDK 错误码 | `60001` = 套餐余额不足或空间过期 |
| Excel 分段 | 默认首行为表头；一个 sheet 仅一个「表头+内容」表格 |
| 逻辑分支 | 自上而下短路，首个命中即止；末端为 Else；分支间节点不可互访 |
| 子流程节点 | 只能选已发布的 Flow；同步阻塞 |
| 多环境 | 激活后不可还原为普通 Flow |
| 定时任务 | 运行参数创建时固定，不随时间动态变化 |
| API Key 兼容外形 | 竞品为 Workspace 级、重新生成后旧 Key 立即失效；本项目仍保留 `Access-Key + Workspace-Id` 请求外形，但实际使用具 scope、资源绑定、到期与撤销语义的凭据，见 ADR-003 |
| 权限 | G0/G1 仅实现统一 `AuthorizationDecision` fail-closed，`allow` 缺失不授予权限；兼容 profile 只是未来独立 envelope/migration 的受控研究项，不能启用 floating binding 或 credential fallback |
| 图文分类器 | 0 积分 |
| 多模态积分 | 与文本独立计算，图片/视频按张数 |

## 5. 执行引擎设计

```
Request
  │
  ▼ Authenticate        # 服务端可信 principal；浏览器 exchange 后每次请求 exact 校验 canonical Origin/CORS
  ▼ Load Sealed Artifact# 编译只发生在发布期；请求只读取固定 compiled hash/closure，不运行时重编译 latest
  ▼ Admit Transaction   # 解析同类型 active revision/profile；固定 Plan + 预扣 + accepted receipt/outbox
  ▼ Plan                # 拓扑排序 + 并发闸门；只读取已固定的 target/Plan
  ▼ Execute Loop ──────────────────────────────────────┐
  │   ├─ 取就绪节点 → 解析变量（双语法 resolver）        │
  │   ├─ 权限前置检查（固定 Plan + call-time revoke/resource/credential epoch 收窄） │
  │   ├─ 执行（超时/重试/异常设置降级输出）              │
  │   ├─ Step Boundary Transaction                      │
  │   │    └─ step/checkpoint/event/usage/outbox 原子提交 │
  │   ├─ Human Gate Transaction                         │
  │   │    └─ WAITING/checkpoint/gate/event/outbox 后释放 Worker │
  │   └─ 分支短路 / 循环计数 / 子流程同步阻塞 ───────────┘
  ▼ Finalizer Transaction # 唯一终态 event + 账务结算/释放 + terminal snapshot + idempotency replay grace
  ▼ Project             # outbox 唤醒 SSE、统计、Webhook 与 OTel 投影；run_logs 仅为兼容读模型
```

`NodeExecutor`、`RunCtx`、`PlanCtx`、checkpoint、HumanGate 与错误/取消语义以 [Flow IR v1](./architecture/flow-ir-v1与运行时契约.md) 为准；Agent 主循环以 [Agent Runtime / Strategy ABI v1](./architecture/agent-runtime-strategy-v1.md) 为准；嵌套依赖与副作用上限以 [Compiled Capability Closure v1](./architecture/compiled-capability-closure-v1.md) 为准。本文件不再维护第二份 TypeScript 接口。任何 SecretResolver 都只能从已授权的 runtime credential handle 解析，IR/Release/closure 不保存实际 `secret_ref`。

## 6. 部署与数据事实源

首版部署画像、出网规则和组件启用条件以 [ADR-002](./adr/002-部署画像与出网边界.md) 为准。初始 Compose 至少包含 studio、api、worker、postgres(pgvector)、redis、minio，以及按画像启用的 parser/sandbox；Helm 是同一组部署单元的集群投影。

- Postgres 是控制数据、发布版本、运行状态、积分预扣/结算与可审计事件的事实源。
- Redis 仅承担缓存、锁与可重建队列加速，不能成为运行或扣费事实源。
- OpenSearch 是全文检索投影，ClickHouse 是统计/分析投影；二者均通过 outbox/event 投影构建，不能与 Postgres 双写。
- MinIO 保存原始文件和大产物，数据库只保存对象引用、摘要、归属和生命周期元数据。

持久化执行不再以单个 `run_logs.nodes` JSON 作为恢复机制；运行状态机、检查点、事件序列、积分和 SSE 回放契约以 [ADR-004](./adr/004-持久化执行与计费.md) 与 [Flow IR v1](./architecture/flow-ir-v1与运行时契约.md) 为准。
