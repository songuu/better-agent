## 4. 必须原样保留的关键约定

复刻时这些行为不能"优化"，否则与 BetterYeah 不等价。全部集中定义在 `packages/shared`。

| 约定 | 值 |
|---|---|
| 变量语法 | 普通节点 `{{name}}`；**逻辑分支与 Code 节点不加双插值** |
| 节点变量名 | 节点名即变量名：`start.content`、`llm_1`、`{{database_1}}` |
| Webhook start | 变量名就是 `start`，第三方 payload 从它取 |
| 全局变量 | `betterAI.store.set/get`；LLM 内 `{{betterAI.store.get("value")}}`；生命周期覆盖整个 Flow 运行 |
| SDK 命名空间 | `betterAI.agent / session / store`；**Python 仅支持 store，session 暂不可用** |
| session 能力 | `conversationId` / `sessionId` / `agentInput` / `metaData` / `setMetaData` / `initSessionData` / `addChatRecord` / `getChatRecord` |
| betteryeah SDK | 五模块 `llm` / `knowledge` / `database` / `plugin` / `subFlow`；统一返回 `ApiResponse<T>`（`code`/`success`/`message`/`data`/`now_time`/`usage.consume`） |
| knowledge 检索参数 | `hitStrategy`：`MIX` / `KEY` / `SEMANTICS`；`maxResultNum` 默认 3；`similarity` 默认 0.4；`rankingStrategy` |
| SQL 限制 | 必加 `LIMIT`，最多 500 行，未加触发智能拦截 |
| Code 节点 | 必须有 `main`；无 return 则输出 null；输出必须可序列化；JS 仅 CommonJS `require` |
| API 节点 | 超时 300 秒；重试次数可配 |
| 分段 | 超 500 字强制切分；建议每段 500 字 |
| 知识库分段区间 | 「每个段落在 200-1000 个字之内」 |
| 问答 xlsx | 表头在第 2 行；1 问 ≤5 答；问 ≤100 字；答 ≤1000 字；无合并单元格；图片须完整置于单元格内 |
| 近义词 | 实体词 1 个且 ≤20 字；近义词 ≤25 个且每个 ≤20 字；英文逗号分隔 |
| 视频知识 | ≤150MB、≤5 个 |
| 知识标签 | ≤9 个 |
| 批量调试 | ≤200 条；文件字段单次 ≤20 个 |
| 上传文件 | Agent 单次 ≤5 个文件或图片 |
| SDK 错误码 | `60001` = 套餐余额不足或空间过期 |
| Excel 分段 | 默认首行为表头；一个 sheet 仅一个「表头+内容」表格 |
| 逻辑分支 | 自上而下短路，首个命中即止；末端为 Else；分支间节点不可互访 |
| 子流程节点 | 只能选已发布的 Flow；同步阻塞 |
| 多环境 | 激活后不可还原为普通 Flow |
| 定时任务 | 运行参数创建时固定，不随时间动态变化 |
| API Key | Workspace 级；重新生成后旧 Key 立即失效 |
| 权限 | 身份未设或设置不全 → 权限管控不生效（fail-open）；`allow` 不填 = 不做限制 |
| 图文分类器 | 0 积分 |
| 多模态积分 | 与文本独立计算，图片/视频按张数 |

## 5. 执行引擎设计

```
Request
  │
  ▼ Compile(cached)     # flow-ir 静态校验：变量类型/可达性/循环边界/密钥泄漏路径
  ▼ Plan                # 拓扑排序 + 并发闸门 + 积分预扣
  ▼ Execute Loop ──────────────────────────────────────┐
  │   ├─ 取就绪节点 → 解析变量（双语法 resolver）        │
  │   ├─ 权限前置检查（strict_permission_mode 决定策略） │
  │   ├─ 执行（超时/重试/异常设置降级输出）              │
  │   ├─ append 节点日志（入参/出参/耗时/积分）          │
  │   └─ 分支短路 / 循环计数 / 子流程同步阻塞 ───────────┘
  ▼ Emit                # SSE task 事件流 + run_logs 落库 + OTel span
```

`NodeExecutor` 统一接口（S2 spike 冻结）：

```ts
export interface NodeExecutor<C = unknown> {
  type: NodeType;
  validate(config: C, ctx: CompileCtx): ValidationResult;
  execute(config: C, ctx: RunCtx): Promise<NodeResult>;
  // 异常设置：LLM / CODE / API / 知识库 四类节点支持
  onError?: (err: Error, config: C) => NodeResult | 'rethrow';
}

export interface RunCtx {
  vars: VarScope;              // start 字段 + 各节点输出 + betterAI.store
  resolve(tpl: string, mode: 'interpolated' | 'bare'): unknown;
  session: SessionApi;         // conversationId / agentInput / metaData / chatRecord
  credits: CreditsMeter;
  signal: AbortSignal;
}
```

## 6. 部署

| 档 | 形态 |
|---|---|
| 私有化单机 | Docker Compose：api · worker · studio · parser-py · postgres(pgvector) · opensearch · redis · minio · clickhouse |
| 私有化集群 | Helm chart，同上组件 + HPA |
| 离线交付 | 全镜像 tar 包 + 模型权重（embedding / rerank / layout）离线包 |

约束：不引入托管服务（这也是不选 Temporal 的原因——独立集群会抬高私有化交付成本）。持久化执行由 `run_logs` + 节点检查点承担，超长运行场景再评估。
