# ADR-002：部署画像与出网边界

> **状态：已接受（文档级架构决策；尚未实现，真实证据待 G0）**
> **日期：2026-08-24**
> **关联文档：** [技术架构](../04-技术架构.md)、[实施计划](../07-实施计划.md)、ADR-003（多租户与密钥）

## 背景

现有技术架构把 API、运行时、工作流、知识库、插件、沙箱等都画为“服务”，而 Monorepo 规划又把其中大部分定义为逻辑包。实施计划同时要求私有化优先、Compose 与 Helm 双档、全依赖离线可用，并在沙箱风险项中提出“默认禁网 + 白名单出网”。

这几个要求尚未形成一个可交付、可验证的部署边界：

- “离线交付”容易被误解为“运行期绝不出网”，但外部模型、API 节点和插件可能需要网络；
- 没有定义最小部署单元，容易把每个逻辑包过早拆成需要独立运维的服务；
- OpenSearch 与 ClickHouse 被列入完整拓扑，却未说明它们是否是首个可用闭环的硬依赖；
- URL、Webhook、插件和代码沙箱都可能成为 SSRF、密钥泄露或绕过网络策略的入口。

本 ADR 只定义部署与网络的目标规格，不声称当前仓库已经具备这些能力。

## 决策

### 1. 区分交付方式与运行期网络画像

离线安装与运行期网络是两个正交维度：

| 概念 | 定义 | 允许的组合 |
|---|---|---|
| 离线安装 | 交付包包含所需镜像、依赖清单，以及被选用的本地模型权重；安装过程不依赖从公共仓库拉取内容。 | 可与任一运行期画像组合。 |
| 隔离运行 | 运行期不允许到公共网络的出站连接；只允许显式列出的集群内服务和本地基础设施。 | 默认画像。外部模型、外部 API 和公网插件不可用，除非其端点确实位于获准的内部网络。 |
| 受控出网 | 运行期仅可经部署方配置的出网策略访问明确允许的目标。 | 用于外部模型供应商、受管 API、已批准插件或渠道回调。 |

每个部署必须选择一个运行期画像；不存在“不受限制出网”的第三种模式。未显式选择时使用隔离运行。离线安装包不能在运行时隐式启用公网访问，受控出网也不能借由安装器绕过审批。

受控出网策略属于部署级安全配置。工作空间、插件或工作流只能引用已获批准的策略标识，不能自行写入任意代理、任意 IP 或任意 DNS 服务器。

### 2. 首期只定义四个应用部署单元

首期生产画像的应用层固定为四个部署单元；它们可以在单机 Compose 中是容器，也可以在 Helm 中是工作负载：

| 单元 | 责任 | 网络与权限边界 |
|---|---|---|
| Studio | Next.js 管理控制台和静态资源。 | 仅调用 API；不持有数据库、队列、对象存储或供应商密钥。 |
| API | 鉴权、REST、SSE、查询、请求受理与运行状态读取。 | 不直接执行用户代码或文档解析；常规业务路径不发起任意外部 HTTP。 |
| Worker | BullMQ 消费、流程和 Agent 调度、模型/工具调用、定时任务及可靠投递。 | 是外部调用的主要执行面，必须使用统一出网策略和审计。 |
| Parser-Sandbox | Python 文档解析侧车与用户代码隔离执行边界。 | 无公网直连；只通过受控的内部接口读取输入、提交结果。沙箱不因部署采用受控出网而自动获得外网权限。 |

packages 中的 flow-engine、agent-runtime、model-gateway、kb-core、plugin-core、credits、db 等是领域逻辑包，而不是首期独立部署服务。它们随 API 或 Worker 进程加载；只有经过负载、隔离或故障域证据证明必要时，才可另立 ADR 拆分。

### 3. 最小基础设施与后置组件

首个可用闭环的状态存储基线为：

| 组件 | 首期职责 | 是否为最小闭环硬依赖 |
|---|---|---|
| Postgres + pgvector | 业务元数据、事务事实源、权限隔离和基础语义检索。 | 是 |
| Redis + BullMQ | 队列传输、限流、缓存和短期协调；不是业务事实源。 | 是 |
| MinIO（S3 兼容） | 用户文件、解析产物及大体积受控载荷。 | 是 |
| OpenSearch | 中文全文/关键词检索的投影与增强能力。 | 否；在三路检索验收与容量需求确认后引入。 |
| ClickHouse | 观测、统计和积分分析投影。 | 否；不得成为运行恢复或扣费正确性的前提。 |

这意味着 Compose 和 Helm 可以提供 OpenSearch、ClickHouse 的可选 profile/chart，但它们不应阻塞 P0/P1 最小纵向闭环。待需要三路检索或长期统计时，再以容量、可用性和数据同步验收启用它们。

### 4. 出网、密钥与 SSRF 的强制边界

1. **统一出口。** API 节点、插件、模型网关、渠道回调和权限 SPI 的外部请求必须经过统一的受控 HTTP 执行器；不得让业务包直接使用任意网络客户端。
2. **分层默认拒绝。** 隔离运行时，网络策略和应用策略均拒绝公网出站。受控出网时，只允许 HTTPS 或经批准的协议、FQDN、端口、路径范围、方法和速率；最终以网络层策略为准，不能只依赖应用层校验。
3. **SSRF 防护。** 每次连接及每一次重定向都必须重新解析并校验目标，拒绝 localhost、回环、私有网段、链路本地地址、CGNAT、IPv6 本地/唯一本地地址、组播/保留地址及云元数据地址；禁止 file、gopher 等非 HTTP(S) 协议，禁止用户自带代理配置，并防御 DNS 重绑定。跨主机重定向不得携带认证头。
4. **沙箱更严。** 用户代码和解析器默认没有公网 egress；若未来确有业务需求，必须经专门的受限代理或能力令牌授权，并另立 ADR，不可复用 Worker 的通用外网权限。
5. **密钥不随 URL 流动。** 出网端点、认证信息和代理凭据使用密钥引用，不写入浏览器包、请求 URL、SSE 事件、运行日志或对象名。运行时仅向实际需要的 API/Worker 工作负载挂载最小权限密钥。密钥的哈希、轮换和租户归属由 ADR-003 定义。
6. **可审计且脱敏。** 出网审计记录策略标识、目标归一化信息、响应类别、耗时和拒绝原因；不得记录 Authorization、Cookie、请求体中的密钥或完整敏感查询参数。

## 备选方案

| 方案 | 结论 | 原因 |
|---|---|---|
| 将每个逻辑包立即拆成独立微服务 | 不采用 | 当前单人私有化目标会把部署、追踪、版本协同和故障排查成本前置，未证明收益。 |
| 将 OpenSearch、ClickHouse 作为首期硬依赖 | 不采用 | 使最小交付增加两个有状态组件，却不能提高运行正确性或计费正确性。 |
| 只提供“离线交付”，不定义运行期网络 | 不采用 | 无法约束外部模型、插件和用户代码的真实出网行为。 |
| 允许工作流配置任意 URL，靠字符串黑名单防护 | 不采用 | 无法可靠处理 DNS 重绑定、重定向和内网/元数据地址，且难以审计。 |
| 允许受控出网即放开沙箱网络 | 不采用 | 用户代码的风险面与受管 Worker 调用不同，最小权限边界会被破坏。 |

## 后果

正面后果：

- 私有化交付有可验证的最小拓扑，单机与集群形态共享同一责任边界；
- 默认隔离运行适合对数据和网络边界要求高的客户；
- 外部模型/API 的网络访问由显式策略控制，沙箱无法顺带获得外网能力；
- 搜索和分析组件可以按验收需要增加，而非阻碍早期闭环。

代价与约束：

- 接入外部供应商前需要维护 allowlist、代理证书和失败诊断；
- 隔离运行环境需要预置本地模型、解析依赖和所需数据，不能在运行时下载；
- 四个单元并不排除未来拆分，但拆分必须有指标和迁移方案；
- 现有架构图和实施计划中的完整组件清单需要在本 ADR 被接受后同步为“基础”与“可选”两层，避免把图示误读成首期必装清单。

## 验收

以下是该决策实现时的验收条件，不代表已经通过：

1. 能在无公网的目标主机使用交付清单安装四个应用单元与所选基础组件；安装过程不得拉取未随包提供的镜像或模型。
2. 隔离运行画像下，外部模型/API/插件请求被明确拒绝，应用日志能说明是网络策略拒绝而不是业务成功；集群内经配置的依赖仍可正常通信。
3. 受控出网画像下，允许列表中的目标可访问，未列目标、解析到内网的目标和跳转到内网的重定向均被拒绝。
4. Parser-Sandbox 在受控出网画像下仍不能直接访问公网；同时验证 CPU、内存和执行时长限制独立生效。
5. Studio 构建物、SSE 数据、运行日志、出网审计和对象名均不包含可用的供应商密钥或代理凭据。
6. 在 OpenSearch 或 ClickHouse 未部署/不可用的情况下，基础流程创建、执行状态持久化和计费结算仍可运行；增强检索或统计应以降级状态呈现。
7. 对每种允许的外部集成，自动化测试覆盖 DNS 解析、IP 校验、重定向校验、认证头剥离和审计脱敏。

## 后续交付决策与阶段门

这些选择不会改变“四个应用单元、默认拒绝出网、统一出口、Postgres 事实源”的已接受边界，因此不阻塞 G0-01。到达对应部署切片仍未决时，相关能力必须保持关闭或采用表中的最小画像：

| 后续事项 | 最迟决策点 | 未决时默认行为 |
|---|---|---|
| 受控出网代理产品、mTLS、客户 DNS 与 allowlist 审批流程 | 首个受控出网集成上线前 | 仅交付隔离运行画像；外部调用 fail-closed。 |
| GPU/CPU 与本地 embedding/rerank/layout 模型、离线包拆分 | 对应模型进入交付清单前 | 不宣称该模型可离线运行；基础闭环使用已验证画像。 |
| 渠道回调、权限 SPI、MCP 在隔离环境中的替代方案 | 对应渠道启用前 | 入口禁用并返回明确不可用原因，不模拟成功。 |
| 镜像签名、SBOM、离线更新验签和回滚密钥 | 首个客户部署包发布前 | 阻断发布包，不降低为未签名安装。 |
| 解析器与用户代码沙箱是否拆分工作负载 | G2 可执行代码/高风险解析启用前 | 两者都不获得公网 egress；风险或容量证据不足则保持禁用。 |
