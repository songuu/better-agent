# 角色设定深研

> 一手证据：`/搭建Agent/角色设定`、`/搭建Agent/变量`、`/搭建Agent/搭建第一个Agent`、三份官方实战教程（文档QA助手 / 数据分析助手 / 文章分析助手）、案例实践（悦享智居企业知识库Agent助手）。

## 1. 定位

角色设定 **就是** LLM 的提示指令。手册原话：「'角色设定'就是大模型（LLM）的提示指令，也称为Prompt」。

它不是一个"人设字段"，而是整个 Agent 的**唯一 system prompt 载体**——技能说明、工作流程、输出格式、约束全在这里。这决定了复刻时的关键取舍：**技能路由质量与角色设定文案强耦合**，不存在独立的 router 配置。

## 2. 双轨编写模式

| 模式 | 存储形态 | 编辑体验 | 权重 |
|---|---|---|---|
| 文本模式 | 单一 markdown 字符串 | 自由书写，全屏，AI 生成/优化 | 无 |
| 结构化模式 | 主题数组（每项含 key / content / weight） | 勾选 + 输入生成，一键同步技能 | **每主题可调权重**，「动态影响Agent对每个主题的执行效果」 |

两模式都配 AI 助手，可一键生成提示词，另有「ai优化」给改进建议。

复刻要点：两模式必须能互转。文本 → 结构化靠标题切分，结构化 → 文本靠模板渲染 + 权重转成强调副词/重复度。见 §7。

## 3. 官方实证样本对照 —— 段名不统一

四份官方教程的段落结构互不相同，说明**段名是自由的，不是枚举**。手册明确：这些标签「都是根据实际情况可选」，还可自行增加如「#约束」「#禁止」「#注意」。

| 样本 | 模型 / 创造性 | 段落结构 | 挂载 |
|---|---|---|---|
| 手册骨架示例（新闻助手） | — | `# 角色` `# 目标` `# 技能` `# 要求` `# 工作流` `# 输出格式` | 搜索插件 |
| 文档QA助手 | betteryeah-32k / 0.3 | `# 角色` `# 目标` `# 要求` | 仅知识库，无技能 |
| 数据分析助手 | — | `角色` `目标` `要求` `输出格式` | 数据表（Excel 导入） |
| 文章分析助手 | GLM-4 / 0.7 | `Role` `Workflow` `Constraints` `Profile`（英文段名） | Flow「文章阅读器」 |
| 悦享智居案例 | 多模态模型可省插件 | `角色` `技能` `任务` `要求` | 4 个知识库 + 视频/图片问答插件 |

复刻结论：**不要把段名做成枚举校验**。存 markdown 原文 + 可选结构化主题数组，段名自由。

## 4. 段落语义规范

| 段 | 手册原意 | 反模式 |
|---|---|---|
| 角色 / 目标 | 先确定 AI 要做的事——「是解答问题、提供创意、还是执行某项任务？」 | 角色过宽。手册要求「一个Agent尽量充当一个角色」 |
| 技能 | 「告诉大模型，它拥有哪些技能，可以做哪些事情」，可拆技能1/2/3 | 与技能说明书表述矛盾 → 两处打架 |
| 要求 | 「避免使用模糊或双关的词汇」，直接简洁减少误解 | 模糊副词（尽量 / 适当） |
| 工作流 | 按序列出执行步骤（先搜索 → 甄别 → 总结输出） | 步骤与实际挂载技能不对应 |
| 输出格式 | 长度、风格、结构要求，示例「标题：/ 摘要：/ 链接：」 | 只说"美观"不给结构 |

从四份实证样本归纳的高效写法：

| 手法 | 实证原文 |
|---|---|
| 出处约定给**字面格式** | 文档QA助手：`【来自于 文件名 段落】` |
| 排行类问题**指定明细粒度** | 数据分析助手：要求给出 `排行的top10明细` |
| 兜底话术**写进约束段** | 文章分析助手：内容为空时回复"链接安全策略限制、读不到内容，换一个试试" |
| 禁止项**给后果**（压强式） | 悦享智居：「不要对知识库的文字内容进行加工，否则你会受到严重惩罚！！！！」 |
| 负向边界**明确写死** | 文章分析助手：「禁止回答url中不存在的内容」 |
| 路由规则**表格化进「任务」段** | 悦享智居：5 类用户意图 → 4 个知识库 |
| 渲染要求**指定格式载体** | 数据分析助手：`请以markdown表格的形式呈现，确保美观`；文档QA助手：「以图文并茂的方式」 |

## 5. 结构化模式七主题

| 主题 | 交互形式 | 字段 / 行为 |
|---|---|---|
| 角色主题 | 勾选 + 输入 | 【角色信息】【使用场景】【工作任务】【人设性格】【人设语气】【回答长度】 |
| 背景主题 | 输入业务说明 | 生成背景知识 |
| 技能主题 | **【一键同步】** 已有技能和工作流 | 输入名称与描述可自动优化技能 Prompt |
| 任务主题 | 勾选任务与说明 | 生成执行步骤 |
| 要求主题 | 勾选要求选项 | — |
| 输出格式主题 | 勾选或输入 + 添加示例 | — |
| 自定义主题 | 输入需求内容生成 | 其他主题不够用时自建 |

**技能主题的「一键同步」是关键联动**：角色设定里的技能段能从已挂载技能列表自动生成，避免 §4 的"两处打架"反模式。复刻必须实现这条双向链路（技能变更 → 提示同步角色设定）。

权重语义：「通过调整每个主题的权重，动态影响Agent对每个主题的执行效果」。手册未公开权重取值范围与实现方式，见 §8 复刻设计。

## 6. 运行时装配顺序（推断）

手册未公开 system prompt 拼装顺序。以下基于五条硬证据反推，实现时按此落地并标注为自定规格：

| 证据 | 来源 |
|---|---|
| 角色设定是唯一 system prompt 载体 | 角色设定页 |
| 技能说明书独立存储，同样进 prompt | 技能页 |
| 知识库说明书与技能说明书同构 | 知识页 |
| 变量运行前替换：`你好，我叫{{name}}` → `你好，我叫张三` | 变量页 |
| 强制查询先检索再组织回答 | 知识页 |

推断装配：

```
[1] 角色设定（变量已插值；结构化模式按权重渲染）
[2] 技能清单 → function/tool schema（技能描述 + 输入描述）
[3] 知识库清单 → 按需查询的库以说明书形式进 tool schema
[4] 强制查询的检索结果 → 注入上下文
[5] 数据表描述（自动生成描述）
[6] 会话历史（受子Agent通信方式裁剪）
[7] 当前用户输入
```

## 7. AI 辅助四条链路

| 链路 | 输入 | 输出 | 首次出现 |
|---|---|---|---|
| AI创建Agent | 一句话需求 | 完整 Agent（需灰度申请） | 2024-04-19 |
| AI生成 | 关键信息 | 角色设定 Prompt | 2024-08-29 |
| AI优化 / Prompt分析进阶 | 现有 prompt | 建议 + 直接应用 + **优化前后对比（含流程图对比）** | 2024-12-26 |
| 根据技能优化 | 知识库/插件/工作流/数据库/子Agent 描述 | 重写 prompt 的技能段 | 2025-05-29 |

配套：**透视图解读**（Prompt → 透视图，帮助读懂结构，2024-08-29）；结构化模式**技能主题一键同步**。

## 8. 开场白与开场引导

两个独立字段，均不在 §3 段落体系内（属 Agent 配置而非 prompt 段）。

| 字段 | 文章分析助手实证 | 作用 |
|---|---|---|
| 开场白 | 主动邀请用户丢一个网页链接过来 | 声明输入形态 |
| 开场引导 | 一条知识库文档链接 + "相似度是什么意思？" | 给可点击的示例提问 |

悦享智居案例把「开启开场白做提问引导」列为两处关键微调之一，理由是降低上手成本。

**推荐问题**是第三个独立机制（对话后生成，三种来源：根据回答生成 / 知识库生成 / 对话上下文），不要与开场引导混为一谈。

## 9. 变量插值与作用域

语法双花括号，手册示例 `{{character}}`、`{{background}}`、`{{role}}`。定位原话：「用于做一些动态的设定，允许在外部修改Agent的局部提示词」。

| 赋值通道 | 时机 | 持久化 |
|---|---|---|
| 会话界面填写 | 「每次开始新会话，需要使用者提前输入变量内容」 | 否 |
| API `inputs` | 每次请求 | 否 |
| SDK `mount({agentMetadata})` | 挂载时；Prompt 内 `{{xxx}}`，Flow 内 `betterAI.session.agentInput.xxx` | 否 |
| SDK `saveVariables()` | 显式调用 | **是** |

权限变量与 Mock 模式变量**不进 prompt**——属控制面，分别驱动权限裁剪与技能 Mock。

## 10. 复刻实现设计

```ts
// packages/agent-runtime/src/role-setting.ts
export type RoleSettingMode = 'structured' | 'text';

export interface RoleSetting {
  mode: RoleSettingMode;
  text?: string;                       // text 模式：markdown 原文，段名自由
  themes?: RoleTheme[];                // structured 模式
  opening?: { greeting?: string; guides?: OpeningGuide[] };  // 开场白 / 开场引导
}

export interface RoleTheme {
  key: 'role' | 'background' | 'skill' | 'task' | 'requirement' | 'output' | string;
  title: string;                       // 渲染出的段标题，自由文本
  content: string;
  weight: number;                      // 0-100，默认 50
  fields?: Record<string, string>;     // 角色主题：角色信息/使用场景/工作任务/人设性格/人设语气/回答长度
  syncedFromSkills?: boolean;          // 技能主题「一键同步」标记
}
```

权重实现（手册未公开，自定规格）——三方案取 A+B 组合：

| 方案 | 做法 | 评价 |
|---|---|---|
| A 强调渲染 | weight ≥70 加 `【重要】` 前缀；≥90 追加一次要点复述 | 可解释、可 diff、无需模型支持 ✅ |
| B 位置排序 | 高权重段渲染靠后（利用近端效应），低权重靠前 | 与 A 叠加，零成本 ✅ |
| C 结构化标注 | 权重写成 XML 属性喂模型 | 依赖模型遵循度，不可预测 ❌ |

两模式互转：

```
text → structured   按 markdown 一级/二级标题切分，标题作 title，weight 统一 50
structured → text   按 weight 排序（方案 B）→ 渲染 `## {title}` + content（方案 A 前缀）
```

**互转必须无损往返**：`structured → text → structured` 后 title 与 content 完全一致，weight 归 50。这条要写成单测。

装配器：

```ts
export interface PromptAssembler {
  assemble(input: {
    role: RoleSetting;
    variables: Record<string, unknown>;   // {{}} 插值
    skills: ToolSchema[];                 // 技能说明书 → tool schema
    knowledge: ToolSchema[];              // 按需查询的知识库说明书
    forcedContext?: string;               // 强制查询的检索结果
    tables?: TableDesc[];                 // 数据表自动生成描述
    history: Message[];                   // 受子Agent通信方式裁剪
  }): { system: string; tools: ToolSchema[]; messages: Message[] };
}
```
