## 1. 已证实类型、待证实入口与项目扩展

当前可引用的 BetterYeah Agent 技能手册明确写的是两种：「技能分为两种：插件与Flow」。公开资料还给出了 SubAgent 的上下文配置。**BetterYeah 独立 Skill 入口**能否绑定至 Agent、其保存对象以及发布/更新/撤销生命周期，当前没有足够公开证据，列为 R-A7 待补。另一方面，Dify、Coze Coding、Stack AI、Gumloop 已给出 `SKILL.md` 型过程包的官方证据，因此本项目可以设计独立 `InstructionSkillRelease`，但它不能与 BetterYeah 兼容结论或 `skill_pack` 混为一谈。

| 类别 | 证据状态 | 本质 / 说明书 | 当前处理 |
|---|---|---|---|
| 插件 Plugin | **[官方事实]** | 平台封装的即插即用工具；技能说明书平台预填、可改。 | 可进入兼容研究与本项目能力 binding。 |
| 工作流 Flow | **[官方事实]** | 提前编排好的流程，需要时执行；说明书必须自己填。 | 可进入兼容研究与本项目能力 binding。 |
| 子Agent | **[官方事实 + 待补]** | 公开资料确认其上下文传递模式；完整保存/发布/嵌套运行语义仍需 R-A7/R-A8 实验。 | 仅按已公开模式建模，未证实处不作兼容承诺。 |
| 独立 Skill 入口 | **[待补实验]** | 是否可作为 Agent capability、如何绑定及其生命周期未知。 | R-A7 未完成前不写成已验证平台能力。 |
| `InstructionSkillRelease` | **[本项目设计 + 横向官方参考]** | 版本化 `SKILL.md`/references/scripts/assets 过程包；指导模型但不直接授予能力。 | 作为通用自有资源建模；BetterYeah 兼容投影仍受 R-A7 阻断。 |
| `AgentStrategyRelease` | **[本项目设计 + Dify 官方参考]** | 控制推理循环、路由、工具选择和终止；不是 Tool 或角色 Prompt。 | 独立 pin、允许 Binding、迭代/调用预算与审计。 |
| `skill_pack` | **[本项目扩展]** | 把多个已绑定能力组合为可审计、固定成员的发布单元。 | 不能反推或宣称为 BetterYeah 独立 Skill 的既有语义。 |

BetterYeah 独立 Skill 的兼容层只有在 R-A7 留存官方材料或受控实验材料并通过架构评审后才可引入；本项目 `InstructionSkillRelease` 的存在和[实施计划](07-实施计划.md)的 G1-A6 API/SSE/browser 投影都不能替代该证据。

两类基础型的差异，手册原话：
- Plugin —「即插即用的工具，可以立即被使用」
- Flow —「提前编排好工作流，需要的时候，执行这个工作流」

插件与 Flow 的分工判据：插件开箱即用、交付完整功能；Flow 内部实现由用户掌控，能覆盖更复杂更贴业务的流程。举例——需要「查询企业订单并筛选最近 5 天未成交订单」这类业务逻辑就建 Flow。

## 2. 技能说明书 = 双字段

关键发现：说明书不是一段文案，是**两个独立字段**。文章分析助手教程给出实证：

| 字段 | 实证内容 | 作用 |
|---|---|---|
| 技能描述 | `这个技能是从用户的输入中总结文章内容` | 让模型判断**何时调用** |
| 输入描述 | `一段包含链接的问题` | 让模型知道**抽什么参数** |

插件侧同构。`/插件/在Agent中使用插件` 原话：「所有插件中都会有技能描述配置，用于让大模型理解插件的作用和调用插件的时机」，入口是「Agent 编辑页面 - 技能 - 插件 Tab - 设置按钮」。

手册另给一个含触发条件的写法（创建钉钉日程）：`用于创建日程，当有行程、会议、工作相关的内容时请调用它`——把 what + when 压进一个字段。

配置前提原话：「提前向Agent描述，这个技能是做什么的，它的输入参数是什么。」

## 3. 路由机制

触发由模型自主判断，非规则配置。原文：「Agent会在你和它的对话内容中，自己判断该调用什么技能。」

两阶段：

| 阶段 | 依据 | 手册实证 |
|---|---|---|
| 选技能 | 技能描述 | 用户说"明天开会" → 选日程技能而非搜索技能 |
| 抽参数 | 对话上下文 | 搜索例：关键词「是从我的对话中'我想知道周杰伦最近的演唱会'，提取的出来的」；日程例：Agent「把开始时间和结束时间都整理出来，变成了技能的输入参数」 |

无 topK、无置信度阈值、无多技能并行编排的**公开配置项**。官方材料只足以确认模型会参考对话与说明书进行选择，不能证明内部“完全只有 prompt 路由”。复刻设计不把这一未知实现当作安全边界：模型只在 `ResolvedAgentPlan` 已授权的能力描述中选择，实际执行仍由类型化执行器、资源 pin 和运行审计约束。

## 4. 控制开关

| 开关 | 语义 | 出现 |
|---|---|---|
| 强制调用工作流 | 指定某工作流后每次提问都走它，绕过自主判断 | 2024-06-13 |
| 强制查询（知识） | 每轮先检索，不由模型判断 | 初始；悦享智居案例的关键调优项 |
| 子Agent 权重 | 权重越高越优先调用 | 2025-07-03 |
| 技能开关 | 决定子Agent 执行时是否调用对应技能 | 2025-08-14 |
| 插件参数默认值 | AI 未从对话中明确提取则用默认值 | 2024-07-11 |
| 输入展示 | 取值含「表单形式」——调用时直接展示表单，用户通过表单与工作流交互 | 2024-07-11 |
| 输出方式 | 已知取值含「不处理直接输出」（Mock 验证用途）；支持批量设置 | 2026-01-15 |
| 隐藏技能图示 / 隐藏技能名称 | 调试、对话、客户端、SDK 中隐藏调用过程图示，仅呈现结果；钉钉侧同样生效 | 2025-01-09 / 2025-06-19 |
| @Agent | 多 Agent 编排下「通过@某个Agent来执行特定的任务」 | 2025-07-17 |

“输入展示=表单形式”描述的是调用前的**输入交互**；“不处理直接输出”描述的是调用后的**输出处理**。二者可以同时出现，不能压缩成同一个 `outputMode` 枚举，也不能由展示选项改变授权、执行器或副作用分类。

## 5. 子Agent 三种通信方式

公开资料确认了三种可配置的上下文传递模式，决定主 Agent 向子 Agent 传什么上下文。是否还存在其他多智能体控制面（例如递归、并发、预算、取消或委派策略）尚未公开，不能因未见配置项而断言不存在。

| 公开模式 | 公开传递内容 | 本项目适用建议 **[设计推断]** | 成本估算 **[设计推断]** |
|---|---|---|---|
| 同步对话记录 | 完整历史 | 兼容观察只证明“完整历史”这一产品选项；本项目只能实现为经过消息/字段 allowlist、分类上限、脱敏和 turn/token 窗口裁剪的 `eligible_history`，不得传 raw full history | 最高，token 随轮次线性增长 |
| 总结历史记录 | 压缩摘要 | 长会话、跨主题 | 中，多一次 LLM 调用 |
| 仅传用户问题 | 当前轮问题 | 无状态工具型子Agent | 最低 |

配套能力：自动更新子Agent描述（含新旧差异对比，2025-05-29）、单一技能同步（2025-08-14）、Prompt「根据技能优化」——依据知识库/插件/工作流/数据库/子Agent 描述重写 prompt 技能段。

## 6. 任务 = 异步技能调用

原文定义：「任务就是**异步调用技能（插件或工作流）**」。

| 维度 | 规则 |
|---|---|
| 前置条件 | 「任务需要运行'插件或工作流'，请确保你的 Agent，已经添加了插件或工作流」 |
| 开关位置 | 编排 - 规则，改完需保存 |
| 配置项 | 在效果预览选择插件、执行时间、输入参数 |
| 用户体验 | 「使用者无需等待，可以和 Agent 进行下一轮对话」，完成后「Agent 会把结果推送给用户」 |
| 定时 | 支持重复，例「每天早上10点帮我搜索AI相关的新闻」 |
| 立即运行 | 有，供测试 |
| 预设任务 | 开发者从编排页预先下发；「对使用者是默认关闭，需要使用者自己选择开启」；「使用者无法修改这个任务，只能选择使用或者不使用」 |

设计动因是解阻塞：此前「需要这个技能执行完成，使用者才可以和它进行下一轮互动」，长耗时技能在 ToB 场景很痛。

复刻的安全默认值：任务 binding 仅接受 `plugin` 或 `flow`，且必须 pin 到已发布、输入/输出契约已校验的目标。若未来要支持知识库、数据库、本项目扩展的 `skill_pack` 或子Agent 作为任务目标，必须先新增该 kind 的任务适配器，声明触发输入、授权主体、副作用、幂等键、取消/恢复与 Run 审计；未定义适配器的 kind 一律拒绝发布。这个限制是设计选择，不是对竞品能力范围的额外断言。

## 7. Mock 模式完整语义

理念：**假装执行并真实返回模拟结果**。

| 项 | 规则 |
|---|---|
| 可 Mock 对象 | 知识、工作流、插件、子Agent（含 A2A）。**数据库暂不支持** |
| 入口 | Agent 中开「Mock模式变量」→「去配置」→ Mock 数据配置弹窗 |
| 自动填入 | 把技能名称直接写进 Mock 数据，免手填 |
| True | 用模拟数据 |
| False | 绕过该技能的 Mock，走真实调用 |
| 未设置 | 「则不会使用Mock数据」 |
| 批量导入 | 参数必须写 True/False，**大小写不敏感**；写错「会导致该条数据被过滤处理为空」 |
| 生效两步 | 弹窗保存 Mock 数据 → Agent 配置界面「保存并生效」 |
| 验证来源 | ① 查运行日志 ② 把技能输出设为「不处理直接输出」 |

使用建议：初次验证功能启用 Mock；已上线功能用 Mock 变量逐条控制部分数据的测试方式。

## 8. 知识 = 可共享说明书的能力绑定（不是独立 Skill）

按需查询的知识库需要「知识库说明书」，手册原话作用「类似技能说明书」，例：`当问到读书相关内容时，请调用这个知识库`。说明书按上传内容自动生成，也支持自定义。

数据表同理——数据分析助手教程中导入 Excel 后点「自动生成描述」，为表生成说明书帮助 Agent 理解表内容。

**结论：说明书是贯穿资源的统一抽象。**

| 资源 | 说明书字段 | 生成方式 |
|---|---|---|
| 插件 | 技能描述（+ 输入描述） | 平台预填，可改 |
| 工作流 | 技能描述 + 输入描述 | 必须手填，可 AI 生成 |
| 子Agent | 技能描述 | 自动生成 + 自动更新 + 差异对比 |
| 知识库 | 知识库说明书 | 按上传内容自动生成 |
| 数据表 | 表描述 | 自动生成描述 |

复刻要点：这五类可以统一成 `CapabilityBinding` / `CapabilityDescriptor`，用于发布校验、版本 pin、说明书、可见性、grant 交集和模型可调用描述；**不能**据此把它们编译成同一种执行器或同一个 `ToolSchema`。

| capability kind | 统一描述可表达的内容 | 必须类型化的执行、授权与审计 |
|---|---|---|
| 知识库 | 说明书、检索输入契约、知识库版本 pin、可见性。 | 按需检索或强制检索、用户/语料 grant、命中文档/块/版本及引用审计。 |
| 数据库 | 表/逻辑操作说明、输入 schema、数据库资源 pin。 | 表/列/行策略、读写区分、参数化操作、结果脱敏；写入必须有 operation key/补偿或显式人工处置，且**永远不可 Mock**。 |
| Flow | 技能描述、输入/输出 schema、固定 `flow_version_id`。 | 调用已发布版本、子 scope、节点副作用、检查点与子步骤审计。 |
| 插件 | 技能描述、JSON 输入契约、工具 schema/版本 pin。 | `CredentialRequirement` 与 Deployment mapping 的运行时最小授权、远程调用副作用、operation key 与回执摘要；Release/Binding 不保存实际 `secret_ref`。 |
| `skill_pack`（本项目扩展） | 包描述、成员清单/版本哈希。 | 展开为固定成员 binding；每个 exposed operation 必须 seal 到唯一 member binding path、target pin 与 operation hash，零匹配/多匹配均拒绝发布；包本身不是绕过成员授权的万能执行器。 |
| 子Agent | 描述、已发布 Agent Release pin、输入契约。 | 父/子 grant 交集、通信方式、最大深度/预算、嵌套 Capability Call（异步时 child Run）与回传审计。 |

因此，“统一”只解决发现和绑定重复，不能消除分支：调用器必须按 kind 选择执行器，授权器必须按 kind 计算 grant，Run 必须按 kind 记录能解释的输入/输出引用与副作用回执。

Instruction Skill 与 Agent Strategy 不进入上表的 `BindingKind`：Instruction Skill 必须以 workspace-scoped、kind-safe 的 `PublishedResourcePin<"INSTRUCTION_SKILL_RELEASE">` 进入 Agent Release，禁止裸 `skill_release_id`、跨 Workspace UUID 或 floating latest；Skill 激活只装配经校验的过程说明，Strategy 只从 `ResolvedAgentPlan` 已允许的 closure-unique Binding path 目录选择。两者分别以内容/实现 hash、允许 Binding、上下文/迭代/调用预算进入 Agent Release。**G1 的 Skill script 固定为 inert asset，不可执行**；未来若解锁执行，必须另行注册为受 sandbox、egress、schema、凭据和副作用策略约束的 `code_tool` Binding，不能借 Skill 激活隐式扩权。G1 必须有明确 owner：skill contract/parser 校验 closed manifest、路径、来源与 hash，publisher/compiler seal binding 并生成 inert descriptor，Agent runtime 只消费 descriptor；缺任一层都拒绝发布/准入，不能临时读取包目录或静默忽略 Skill。

## 9. 意图识别增强 = 路由 RAG 化

官方给出的突破 prompt 层路由天花板的解法（Flow 模板）。

适用场景（手册原文）：意图类别超过 10 个难以维护；意图属专业领域，「缺乏说明便难以分辨」。

编排三段：

```
用户问题 → ① 从意图示例库匹配相似问题与意图示例
        → ② 整理匹配到的全部示例
        → ③ 传给意图识别节点 → 各分类分支接对应流程
```

示例库设计（唯一给出具体规则的部分）：建一个**问答库**，「【问题】使用用户的问题，【答案】使用意图名称」。

价值：维护成本从"改分类说明"转为"维护示例库"，且示例库可由真实用户问法持续喂养。

**复刻优先级高**——这是 BetterYeah 自己给出的路由可扩展方案，比堆已建模能力绑定的说明书更可持续。

## 10. 路由失败模式与调优手册

从手册反复强调的点 + 四份实证反推：

| 失败模式 | 症状 | 调优手段 |
|---|---|---|
| 技能描述过泛 | 该调不调 / 乱调 | 描述写成 what + when 两句，参考 `用于创建日程，当有行程、会议、工作相关的内容时请调用它` |
| 角色设定技能段与说明书矛盾 | 行为不稳定 | 用结构化模式技能主题「一键同步」 |
| 参数抽不全 | 技能报错 | 补「输入描述」；设插件参数默认值 |
| 该查知识库却没查 | 答非所问 / 幻觉 | 开**强制调用**（悦享智居案例的关键微调） |
| 意图类别过多 | 分类错乱 | 上 §9 意图识别增强模板 |
| 多技能竞争 | 选错技能 | 子Agent 加权重；或拆成多个 Agent 用 @Agent 显式指派 |
| 长耗时技能阻塞对话 | 用户等待 | 改用**任务**（异步） |
| 联调时依赖未就绪 | 无法测试 | 开 Mock 模式，`不处理直接输出` 验证 |
| 技能过程暴露给终端用户 | 体验杂乱 | 隐藏技能图示 / 隐藏技能名称 |

## 11. 复刻实现设计

发布器统一编译的是不可变的 capability binding；运行器再按 kind 选择执行器。以下仅为研究阶段的**非规范展示投影**，不是现有代码，也不得直接生成 schema；规范类型以 [Agent Release v1](./architecture/agent-release-v1与能力装配契约.md) 与 [Compiled Capability Closure v1](./architecture/compiled-capability-closure-v1.md) 为准：

```ts
// packages/agent-runtime/src/capability-compiler.ts
// 本研究文档不复制第二份公共字段或开放 config；实现直接消费规范 closed union。
export type CapabilityBinding = CapabilityBindingV1;

export interface AgentTaskBinding {
  target_kind: 'plugin' | 'flow';  // 其他 kind 需先定义 TaskAdapter 再扩展
  target_binding_id: string;
  schedule: ScheduleSpec;
  input_schema: JsonSchema;
}
```

`CapabilityBindingV1` 是唯一字段事实源；本文件不再重述 `weight/force/defaultParams` 等公共字段。规范 schema 必须按 `kind + target_kind + config.schema_version` closed 校验；错 kind、未知字段、G1 DB write、Flow/SubAgent detach 和 `floating_latest` 在 publisher/admission fail closed。

编译与解析链路：

```
Agent / Skill / Strategy / Experience Drafts
  → 分别发布 immutable Release + capability closure / dependency manifest
  → Deployment revision 固定 Agent+Experience Release、channel/policy/credential mappings
  → active pointer 只在准入事务解析并固定 revision
  → 调用时按可信主体解析 AuthorizationDecision ∩ Release/closure ∩ Deployment，并快照决策
  → ResolvedAgentPlan（仅保留本次可用的 typed capability）
  → kind executor（knowledge / database / flow / plugin / skill-pack〔本项目扩展〕/ subagent）
  → Run step、attempt、结果引用与副作用审计
```

关键分支的安全含义：

| 配置/状态 | `ResolvedAgentPlan` 与执行规则 |
|---|---|
| `discoverability='forced'` + `KnowledgeBindingConfigV1.selection='force'` | 先校验资源 grant、输入、预算和 kind 契约，再按已发布顺序生成显式计划步骤；强制知识检索结果可注入上下文。无权/不可用时失败，不得退化为“让模型猜”。 |
| `input_interaction_mode='form'` | 在调用**前**收集并校验输入；它可与 `output_handling_mode='raw'` 同时存在，二者绝不共用字段。 |
| `output_handling_mode='raw'` | 在调用**后**选择直接投影已授权、已脱敏结果；不改变资源身份、授权或审计。 |
| `mock_safe=true` | 仅测试策略允许时短路对应 executor 并审计模拟数据版本。`database` 固定为 `false`，不能被 Mock 变量覆盖。 |
| 子Agent 权重 / 通信方式 | `SubagentBindingConfigV1.routing_priority_weight` 只影响已授权、已进入 closure 的合格候选排序，不能绕过授权或扩展候选集；通信方式使用带 message/field allowlist、数据分类、脱敏、max turns/tokens 与 projection hash 的 `SubagentContextProjectionV1`。`eligible_history` 不是 raw full history；子Agent 仍需独立 Release pin、grant 交集、深度/预算与嵌套 Call（异步时 child Run）。 |
| 异常自动重试 | 是 Draft 的请求和 Release 的上限，不是全局重放许可。仅 `safe` 或带已提交 operation key 的 `requires_key` 操作可重试；数据库写入、插件/Flow 的未知或 `unsafe` 写副作用不得自动重试，必须进入 `SIDE_EFFECT_UNKNOWN`/人工处置路径。 |

`CapabilityBinding` 可以让模型看到一致的名称、说明和输入描述，但不能把检索、数据库、工作流、插件或子Agent 伪装为相同的 `ToolSchema`。各 executor 必须在同一 Run 事实模型中写入其特有的资源 pin、授权决策引用、输入/输出安全引用、费用和副作用回执。

## 12. 验收清单

- [ ] 已证实的 Plugin/Flow 与已公开模式下的 SubAgent 可按各自契约挂载；Instruction Skill/Strategy 只引用已授权 Binding 且不能扩权；BetterYeah 独立 Skill 在 R-A7 闭环前不作兼容承诺，`skill_pack` 仅按本项目扩展验收
- [ ] 插件说明书平台预填且可改；Flow 说明书强制填写校验
- [ ] 各类资源共享 capability binding/descriptor，但由各自 executor、授权器和审计字段处理
- [ ] 强制调用 / 强制查询 在授权和预算校验后编译为显式计划步骤，而非仅靠提示词
- [ ] 子Agent 权重影响候选排序；raw full history/system/tool observation 被拒绝，三种通信方式都只基于 versioned `SubagentContextProjectionV1` 的 eligible input
- [ ] 批量添加/移除/启停/设置输出方式可用
- [ ] `PluginBindingConfigV1.default_parameters` 仅在模型未抽到字段时生效，且仍需通过插件输入 schema
- [ ] 任务异步不阻塞对话，完成后推送；预设任务对使用者默认关闭且不可编辑
- [ ] `input_interaction_mode='form'` 与 `output_handling_mode='raw'` 分列建模、可独立组合和验证
- [ ] 任务目标只允许 Plugin/Flow；新增 target kind 必须先提供 TaskAdapter、发布校验和 Run 审计
- [ ] Mock：True 用模拟 / False 真实 / 未设置不 Mock；数据库固定不可 Mock；批量导入大小写不敏感，非法值该条置空

- [ ] 「不处理直接输出」可验证技能输出来源
- [ ] 自动重试按 capability 副作用和 operation key 判定；任何数据库/外部未知写副作用均不能被总开关自动重放
- [ ] 意图识别增强模板可跑通（问答库作意图示例库）
- [ ] 隐藏技能图示/名称在调试、对话、SDK、钉钉四处均生效
