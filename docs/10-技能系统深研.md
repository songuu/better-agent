# 技能系统深研

> 一手证据：`/搭建Agent/技能`、`/搭建Agent/任务`、`/搭建Agent/知识`、`/搭建Agent/Mock模式变量`、`/插件/在Agent中使用插件`、`/插件/什么是插件`、`/Flow/模板/【意图识别增强】模板`、文章分析助手与悦享智居两份实战。

## 1. 技能四型

手册定义技能只有两种：「技能分为两种：插件与Flow」。但更新日志显示实际已扩到四型。

| 型 | 本质 | 说明书 | 首次出现 |
|---|---|---|---|
| 插件 Plugin | 平台封装的即插即用工具 | 平台预填，可改 | 初始 |
| 工作流 Flow | 提前编排好的流程，需要时执行 | **必须自己填** | 初始 |
| 子Agent | 另一个 Agent 作为技能 | 可自动生成 + 自动更新 + 差异对比 | 2025-04-30 |
| Skill 包 | 打包多个工作流 + 插件 | Skill 描述 + 内部工具用法说明 | 2026-03-05 |

两类基础型的差异，手册原话：
- Plugin —「即插即用的工具，可以立即被使用」
- Flow —「提前编排好工作流，需要的时候，执行这个工作流」

插件与 Flow 的分工判据：插件开箱即用、交付完整功能；Flow 内部实现由用户掌控，能覆盖更复杂更贴业务的流程。举例——需要「查询企业订单并筛选最近 5 天未成交订单」这类业务逻辑就建 Flow。

## 2. 技能说明书 = 双字段

关键发现：说明书不是一段文案，是**两个独立字段**。文章分析助手教程给出实证：

| 字段 | 实证内容 | 作用 |
|---|---|---|
| 技能描述 | `这个技能是从用户的输入中总结文章内容` | 让模型判断**何时调用** |
| 输入描述 | `一段包含链接的问题` | 让模型知道**抽什么参数** |

插件侧同构。`/插件/在Agent中使用插件` 原话：「所有插件中都会有技能描述配置，用于让大模型理解插件的作用和调用插件的时机」，入口是「Agent 编辑页面 - 技能 - 插件 Tab - 设置按钮」。

手册另给一个含触发条件的写法（创建钉钉日程）：`用于创建日程，当有行程、会议、工作相关的内容时请调用它`——把 what + when 压进一个字段。

配置前提原话：「提前向Agent描述，这个技能是做什么的，它的输入参数是什么。」

## 3. 路由机制

触发由模型自主判断，非规则配置。原文：「Agent会在你和它的对话内容中，自己判断该调用什么技能。」

两阶段：

| 阶段 | 依据 | 手册实证 |
|---|---|---|
| 选技能 | 技能描述 | 用户说"明天开会" → 选日程技能而非搜索技能 |
| 抽参数 | 对话上下文 | 搜索例：关键词「是从我的对话中'我想知道周杰伦最近的演唱会'，提取的出来的」；日程例：Agent「把开始时间和结束时间都整理出来，变成了技能的输入参数」 |

无 topK、无置信度阈值、无多技能并行编排的公开配置项。**路由完全在 prompt 层**，这是 BetterYeah 架构的核心特征，也是 1:1 复刻时必须接受的天花板。

## 4. 控制开关

| 开关 | 语义 | 出现 |
|---|---|---|
| 强制调用工作流 | 指定某工作流后每次提问都走它，绕过自主判断 | 2024-06-13 |
| 强制查询（知识） | 每轮先检索，不由模型判断 | 初始；悦享智居案例的关键调优项 |
| 子Agent 权重 | 权重越高越优先调用 | 2025-07-03 |
| 技能开关 | 决定子Agent 执行时是否调用对应技能 | 2025-08-14 |
| 插件参数默认值 | AI 未从对话中明确提取则用默认值 | 2024-07-11 |
| 输入展示 | 取值含「表单形式」——调用时直接展示表单，用户通过表单与工作流交互 | 2024-07-11 |
| 输出方式 | 已知取值含「不处理直接输出」（Mock 验证用途）；支持批量设置 | 2026-01-15 |
| 隐藏技能图示 / 隐藏技能名称 | 调试、对话、客户端、SDK 中隐藏调用过程图示，仅呈现结果；钉钉侧同样生效 | 2025-01-09 / 2025-06-19 |
| @Agent | 多 Agent 编排下「通过@某个Agent来执行特定的任务」 | 2025-07-17 |

## 5. 子Agent 三种通信方式

2025-07-03 引入，决定主 Agent 向子 Agent 传什么上下文。这是唯一的多智能体上下文控制手段。

| 方式 | 传递内容 | 适用 | 成本 |
|---|---|---|---|
| 同步对话记录 | 完整历史 | 子Agent 需完整语境（如接续追问） | 最高，token 随轮次线性增长 |
| 总结历史记录 | 压缩摘要 | 长会话、跨主题 | 中，多一次 LLM 调用 |
| 仅传用户问题 | 当前轮问题 | 无状态工具型子Agent | 最低 |

配套能力：自动更新子Agent描述（含新旧差异对比，2025-05-29）、单一技能同步（2025-08-14）、Prompt「根据技能优化」——依据知识库/插件/工作流/数据库/子Agent 描述重写 prompt 技能段。

## 6. 任务 = 异步技能调用

原文定义：「任务就是**异步调用技能（插件或工作流）**」。

| 维度 | 规则 |
|---|---|
| 前置条件 | 「任务需要运行'插件或工作流'，请确保你的 Agent，已经添加了插件或工作流」 |
| 开关位置 | 编排 - 规则，改完需保存 |
| 配置项 | 在效果预览选择插件、执行时间、输入参数 |
| 用户体验 | 「使用者无需等待，可以和 Agent 进行下一轮对话」，完成后「Agent 会把结果推送给用户」 |
| 定时 | 支持重复，例「每天早上10点帮我搜索AI相关的新闻」 |
| 立即运行 | 有，供测试 |
| 预设任务 | 开发者从编排页预先下发；「对使用者是默认关闭，需要使用者自己选择开启」；「使用者无法修改这个任务，只能选择使用或者不使用」 |

设计动因是解阻塞：此前「需要这个技能执行完成，使用者才可以和它进行下一轮互动」，长耗时技能在 ToB 场景很痛。

## 7. Mock 模式完整语义

理念：**假装执行并真实返回模拟结果**。

| 项 | 规则 |
|---|---|
| 可 Mock 对象 | 知识、工作流、插件、子Agent（含 A2A）。**数据库暂不支持** |
| 入口 | Agent 中开「Mock模式变量」→「去配置」→ Mock 数据配置弹窗 |
| 自动填入 | 把技能名称直接写进 Mock 数据，免手填 |
| True | 用模拟数据 |
| False | 绕过该技能的 Mock，走真实调用 |
| 未设置 | 「则不会使用Mock数据」 |
| 批量导入 | 参数必须写 True/False，**大小写不敏感**；写错「会导致该条数据被过滤处理为空」 |
| 生效两步 | 弹窗保存 Mock 数据 → Agent 配置界面「保存并生效」 |
| 验证来源 | ① 查运行日志 ② 把技能输出设为「不处理直接输出」 |

使用建议：初次验证功能启用 Mock；已上线功能用 Mock 变量逐条控制部分数据的测试方式。

## 8. 知识 = 伪技能（说明书统一抽象）

按需查询的知识库需要「知识库说明书」，手册原话作用「类似技能说明书」，例：`当问到读书相关内容时，请调用这个知识库`。说明书按上传内容自动生成，也支持自定义。

数据表同理——数据分析助手教程中导入 Excel 后点「自动生成描述」，为表生成说明书帮助 Agent 理解表内容。

**结论：说明书是贯穿四类资源的统一抽象。**

| 资源 | 说明书字段 | 生成方式 |
|---|---|---|
| 插件 | 技能描述（+ 输入描述） | 平台预填，可改 |
| 工作流 | 技能描述 + 输入描述 | 必须手填，可 AI 生成 |
| 子Agent | 技能描述 | 自动生成 + 自动更新 + 差异对比 |
| 知识库 | 知识库说明书 | 按上传内容自动生成 |
| 数据表 | 表描述 | 自动生成描述 |

复刻要点：这五类在运行时应编译成**同一份 tool schema 列表**喂给模型，而非五套分支逻辑。

## 9. 意图识别增强 = 路由 RAG 化

官方给出的突破 prompt 层路由天花板的解法（Flow 模板）。

适用场景（手册原文）：意图类别超过 10 个难以维护；意图属专业领域，「缺乏说明便难以分辨」。

编排三段：

```
用户问题 → ① 从意图示例库匹配相似问题与意图示例
        → ② 整理匹配到的全部示例
        → ③ 传给意图识别节点 → 各分类分支接对应流程
```

示例库设计（唯一给出具体规则的部分）：建一个**问答库**，「【问题】使用用户的问题，【答案】使用意图名称」。

价值：维护成本从"改分类说明"转为"维护示例库"，且示例库可由真实用户问法持续喂养。

**复刻优先级高**——这是 BetterYeah 自己给出的路由可扩展方案，比堆技能描述更可持续。

## 10. 路由失败模式与调优手册

从手册反复强调的点 + 四份实证反推：

| 失败模式 | 症状 | 调优手段 |
|---|---|---|
| 技能描述过泛 | 该调不调 / 乱调 | 描述写成 what + when 两句，参考 `用于创建日程，当有行程、会议、工作相关的内容时请调用它` |
| 角色设定技能段与说明书矛盾 | 行为不稳定 | 用结构化模式技能主题「一键同步」 |
| 参数抽不全 | 技能报错 | 补「输入描述」；设插件参数默认值 |
| 该查知识库却没查 | 答非所问 / 幻觉 | 开**强制调用**（悦享智居案例的关键微调） |
| 意图类别过多 | 分类错乱 | 上 §9 意图识别增强模板 |
| 多技能竞争 | 选错技能 | 子Agent 加权重；或拆成多个 Agent 用 @Agent 显式指派 |
| 长耗时技能阻塞对话 | 用户等待 | 改用**任务**（异步） |
| 联调时依赖未就绪 | 无法测试 | 开 Mock 模式，`不处理直接输出` 验证 |
| 技能过程暴露给终端用户 | 体验杂乱 | 隐藏技能图示 / 隐藏技能名称 |

## 11. 复刻实现设计

五类资源统一编译成 tool schema：

```ts
// packages/agent-runtime/src/skill-compiler.ts
export interface SkillManual {
  description: string;        // 技能描述 → tool.description（何时调用）
  inputDescription?: string;  // 输入描述 → 拼入 description 或 schema.description
}

export interface CompiledSkill {
  name: string;
  schema: ToolSchema;              // JSON Schema，由插件/Flow start 节点/子Agent 契约生成
  source: 'plugin' | 'flow' | 'sub_agent' | 'skill_pack' | 'knowledge' | 'table';
  enabled: boolean;
  weight?: number;                 // 子Agent 权重
  forceCall: boolean;              // 强制调用 → 绕过模型选择，直接注入
  defaultParams?: Record<string, unknown>;
  outputMode?: 'normal' | 'raw' | 'form';   // 不处理直接输出 / 表单形式
  mock?: { enabled: boolean; data: unknown };
  commMode?: 'sync_history' | 'summarize_history' | 'question_only';  // 子Agent
}
```

调用链关键分支：

```
forceCall=true          → 跳过 LLM 选择，直接执行，结果注入上下文
mock.enabled=true       → 短路执行，返回 mock.data（数据库除外）
weight 排序             → 多个候选子Agent 时排在 tool 列表前部 + 描述加优先级提示
commMode                → 决定传给子Agent 的 messages 裁剪策略
outputMode='raw'        → 技能输出不过 LLM，直接回传（Mock 验证 / 结构化透传）
```
