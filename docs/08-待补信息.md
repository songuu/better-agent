## Agent 配置研究新增待补实证

用户提供的三张 Agent 编辑页截图仅能证明“规则主题/权重、开场、权限变量、Mock、变量、强制调用、任务、快捷入口、技能图示和异常自动重试”等配置入口可见；它们**不是**保存结构、运行语义或对外协议。下表中的实验必须在隔离测试 Workspace 和无生产数据的资源上完成，并保留脱敏后的配置快照、请求/响应和 Run/任务日志。

为避免与 [实施计划](./07-实施计划.md) 的实施切片混淆，以下 `R-A1`~`R-A12` 仅表示研究/实验矩阵；`G1-A1`~`G1-A8` 仅表示本项目实施切片。尤其 `G1-A6` 的 API/SSE/browser 投影不能证明独立 Skill 的 Agent 绑定或生命周期；后者只能由 `R-A7` 的可留存官方材料或受控实验材料闭环，并经架构评审。

| 研究 ID | 待证实的 Agent 行为 | 阻断边界 | 具体获取方式 |
|---|---|---|---|
| R-A1 | 结构化规则主题、权重范围/默认值、自由模式切换、AI 优化后的保存与发布载荷；权重是否影响 prompt 合成还是模型路由 | 阻断编辑器导入/导出、发布 diff 和“权重兼容”夹具；不阻断本项目按 Release 编译的自定规格 | 在官方产品测试 Workspace 建两个仅权重不同的 Agent；浏览器网络面板导出保存/发布请求（脱敏），固定同一测试输入和模型设置，对比版本详情、task trace 与输出；若结果不稳定，只记录载荷差异，不据输出推定内部算法 |
| R-A2 | 普通变量、权限变量与 `{{}}` 的来源、作用域、类型校验、持久化与覆盖顺序 | 阻断变量编辑/会话/任务的字段兼容；不阻断本项目的显式输入 Schema | 用同一 Agent 分别从聊天输入、渠道身份、权限回调和保存变量写入同名值；导出请求、会话/任务日志与错误返回，验证缺值、类型错和重连后的行为 |
| R-A3 | 权限变量与外部权限回调的真实请求字段、资源类型映射、缓存/超时/撤销后的运行时行为 | 阻断权限 SPI compatibility profile 与 Agent 级差异化访问夹具 | 在可控 HTTPS 回调端记录脱敏入站请求；测试空 user list、不同用户、allow 缺失、超时、资源撤销和同会话重试，保存官方产品的可见结果及回调频次 |
| R-A4 | Mock 模式：自动填入的位置、批量 True/False 含义、是否进入已发布版本/外部渠道或仅限调试 | 阻断 Mock UI、批量调试和生产隔离的兼容夹具 | 为每个变量设置真实值与 Mock 值，分别在预览、发布后聊天、API/渠道调用和批量调试中执行；采集输入回显、task trace、版本详情和关闭 Mock 后的差异 |
| R-A5 | “强制调用知识库”的精确定义：触发顺序、未命中/异常/多知识库冲突时是否继续、task 中的证据字段 | 阻断强制检索的兼容行为与故障夹具；不阻断本项目把它建模为可审计 Plan 步骤 | 创建命中库、空库和故意不可用库，分别开启/关闭强制调用并执行相同问题；导出每次 Run 的能力调用/task 日志、引用链接和终态，比较是否真的发生检索与失败后的后续步骤 |
| R-A6 | Agent 数据库能力的可选资源、Schema/operation 暴露范围、读写确认、参数限制、结果截断和失败语义 | 阻断数据库 Agent 能力绑定的产品兼容；不阻断本项目的 allowlist/参数化/默认拒绝设计 | 在官方测试数据库建立只读表、可写测试表和无权表；以不同 Agent 配置执行读取、写入、超限与超时案例，留存配置页、运行日志、数据库审计和回滚后的数据读回 |

| R-A9 | “异常自动重试”开关覆盖的错误类别、次数、退避、任务/聊天差异，以及已发送外部写入后的处置 | 阻断自动重试 UI 和任务兼容；安全默认仍按 ADR-004 的未知副作用不重放 | 用可控的只读临时失败服务和带幂等标记的写入测试服务，分别制造 4xx、5xx、超时、连接中断和调用后断连；从 Run/task/外部审计三侧核对调用次数、间隔与是否重复写入 |

| R-A11 | 开场白、开场提问、AI 自动推荐问题、快捷入口和隐藏技能图示的配置来源与会话投影 | 阻断 Studio UI 和 Web SDK 展示 parity；不阻断安全运行闭环 | 分别手工编辑/AI 生成/删除每项，在新旧会话、不同用户和移动端/嵌入端观察；保存配置版本、首屏 DOM/接口响应与点击后的实际输入或能力调用 |
| R-A12 | Agent 发布后依赖知识库、数据库、Flow、插件、SubAgent，以及独立 Skill 入口（如可绑定）被更新/撤销/删除时，旧会话、重试和恢复如何解析版本 | 阻断“最新解析”类兼容结论；本项目默认以 Release pin 运行 | 发布 Agent A 后依次更新、撤销、删除每个测试依赖；对新会话、已有会话、已排队任务和可恢复失败 Run 逐一执行，收集版本历史、错误码、调用日志和资源读回 |

首版的 `skill_pack` 是本项目将多个已绑定能力组合为一个可审计发布单元的设计扩展；它不能被当作 BetterYeah 独立 Skill 已可绑定 Agent 或已有发布生命周期的证据。若要声明该兼容行为，必须先完成 `R-A7`、留存官方材料或受控实验材料，并经架构评审；`G1-A6` API/SSE/browser 投影不是该证据。

## 获取与闭环规则

每项补齐后必须新增以下三类证据，而不是只更新表格：

1. 来源快照或可复查链接；
2. 兼容规格（字段、限制、错误和安全边界）；
3. 自动化夹具或人工验收步骤，并标明适用的部署画像。

对 `R-A1`~`R-A12` 还必须记录实验的产品版本、Workspace 初始化状态、调用身份、模型/资源版本和采集时间。单张截图、单次自然语言输出或无法复现的 UI 观察都不足以升级为协议；未证实时应保留为“未知”，继续使用 ADR-001~004、Flow IR 与 Agent Release 契约中的安全自定规格。
