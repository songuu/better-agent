## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| flow-engine 语义复杂度被低估 | P1 延期拖垮全局 | S1/S2 spike 先冻结 IR；16 节点分三批交付（核心 6 → 逻辑 4 → 增强 6） |
| 文档解析质量决定 ToB 成败 | 知识库不可用 | 不自研解析，`parser-py` 接现成 layout 模型 + OCR；提前到第 3 周起 |
| 沙箱逃逸 | 安全事故 | S3 先验证；L4 对抗测试；禁网默认 + 白名单出网 + CPU/内存/时长三限 |
| 官方插件 40+ 数量堆积 | P4 爆炸 | P4 只交付框架 + 8 个；其余按框架增量，不进关键路径 |
| 权限 fail-open 复刻带来责任 | 客户数据泄漏 | `strict_permission_mode` 开关 + 配置期校验（无 `user_id` 渠道禁挂非 public 知识库） |
| 截图内信息缺失 | 部分实现只能猜 | 见 `08-待补信息.md`，不阻塞 P0-P2 |
| Agent 无版本管理（BetterYeah 缺口 G1） | 生产 Agent 改坏无法回退 | 1:1 复刻不加版本；但 `agents` 表预留 `version` 字段，后续可开 |
