## 0.1 G0-01 启动前的文档冻结门

以下事项任一未满足时不得启动 G0-01，也不得创建业务 handler/executor；它们只要求设计输入可评审，不要求先拥有尚待 G0 工具链产生的运行证据：

1. ADR-001 至 ADR-004 已接受为文档级目标决策，兼容 profile、部署画像、RLS、凭据与持久化执行的默认值明确；
2. 多租户、RLS、凭据 hash/rotation、资源 scope、Run/计费的目标 DDL 与失败夹具已定义，并明确仍需由 G0-03 转成真实 migration/test；
3. Flow IR v1、Agent Release/Instruction Skill/Strategy/Experience/Deployment、Human Gate、运行状态机、积分预扣/结算、outbox 和 SSE 回放契约已冻结；
4. 已发布资源/版本注册表先于 Run 建立，Run 对 Deployment、Agent/Flow/Skill/Strategy/Knowledge generation release pin 使用同租户可验证引用；
5. REST OpenAPI、SSE 事件、错误码、Idempotency-Key、取消、请求 ID 与 secret redaction 已冻结；
6. 最小纵向闭环的验收样例与失败恢复用例已定义。

此外，2026-08-25 复审新增五个不可省略的设计关闭条件：可信 browser principal/token exchange、active pointer 与已接受 Run 的 epoch 分离、嵌套 `CompiledCapabilityClosure`、Flow/Strategy 可恢复 ABI，以及财务 ledger 不受通用 Run retention 删除。

## 0.2 G0-08 可执行门（进入 G1 前阻断）

| G1-A3 Knowledge 与数据库受限操作 | G1-A1 | 实现固定 Knowledge generation 和一个参数化、只读、限行限时的 Database Operation Release；模型不获得 SQL 连接串、任意表权限或“自由 SQL”。写 operation、补偿与未知写副作用进入 G2 且需单独架构门 | generation/ACL/metadata filter、越权 schema/operation、未绑定参数、超限结果和任何写语句均拒绝；两个 principal 的 delegated ACL 不串用；资源 pin/查询摘要进入 Run 审计 |
| G1-A4 Agent/Strategy/Instruction Skill | G1-A2、G1-A3 | 编译 Agent Release/closure/Plan，实现 Strategy durable loop；Instruction Skill 有 manifest/parser/hash、路径安全、上下文裁剪与 inert activation，required script 以明确错误拒绝；Experience public handle 以不可变映射指向 binding/operation/schema hash | 模型调用前后宕机、预算/迭代/usage receipt、Skill path traversal/hash 漂移/script 执行请求/能力扩张、handle 重复或错配均有确定结果；Skill/Strategy 不能扩权 |
| G1-A5 Worker、Human Gate 与 Join-only SubAgent | G1-A1~G1-A4 | 执行固定 Flow/Agent Plan；同步 Flow/SubAgent 分别使用固定 `flow_execution_id`/`agent_execution_id`、子 Plan hash、checkpoint 与不可变上下文投影；G1 child 仅允许 `join + wait_for_settlement`；Human Input/Approval 原子提交 checkpoint/gate/outbox，resume 先查 mutation receipt 再重验证；重试只能服从已编译副作用策略 | bounded delegation 有 allow-set/expiry/call-limit/reason；child 不二次预留/结算；重启可恢复等待，重复/并发 approve/reject/cancel 只有一个胜出；并行 Gate barrier、Gate disposition、Run terminal 与 `SIDE_EFFECT_UNKNOWN` operator-hold 映射唯一；`safe` / 携带 operation key 的 `requires_key` 暂态错误遵从上限，未知或 `unsafe` 写副作用进入人工处置 |
| G1-A6 API/SSE/browser 投影 | G1-A1~G1-A5 | authenticated browser 先 exchange 为短期 session principal，并在每次 browser 请求 exact 校验 canonical Origin/CORS；将持久化 Run/Step/Event/HumanGate 投影为 Chat、canonical `202 Operation` receipt 和标准判别 SSE event。幂等历史查询先于当前 revision/Gate 重验证；公共面不泄露内部 pin/system/tool 内容 | credential kind/purpose/scope、Origin/null/missing/CORS、伪造 `user.id`、跨 principal conversation/Run read 被拒绝；按 ID 不可见统一 404；非终态长 WAITING key 不释放；同 key 只产生一个 Run/预扣/sequence；oneOf 事件、断线回放与 observe scope 通过机器契约 |
| G1-A7 Evaluation 与 production promotion | G1-A1~G1-A6 | 以不可变 Evaluation Suite/Run 和统一 promotion decision 固定 dataset/evaluator、Agent/Flow/Skill/Strategy/model/Knowledge generation、closure/change-set、成本/延迟/安全阈值；G0 仅允许 development/staging，只有本门通过才解锁 production pointer CAS，回滚只切换既有 Deployment revision | 门未安装、decision 失效、重跑、预算不足或阈值失败均不能 production；fixture 不授生产权限；Agent/Flow 共用 promotion 约束，promotion/rollback 有 diff、审批和精确 Release 组合；`SUSPENDED → ACTIVE` 后旧 Run 仍永久失权而新 Run 成功，`REVOKED` 不可恢复 |
| G1-A8 最小纵向 E2E Gate | G1-A1~G1-A7 | 一个已认证用户经 browser exchange 调用已部署 Agent；Agent 使用固定 Knowledge generation、参数化只读 DB operation 与 inert Instruction Skill，经历一次 HumanGate 后恢复，并以 join-only 子执行终结 | 真实 PostgreSQL 独立 readback、事件/账务/授权审计链一致；failure injection、断线回放、Skill required-script/path traversal/能力扩张、public handle/pack route 错配以及任何 RLS/latest/mock/direct Release entry 绕过均失败 |

G0-05 的发布夹具还必须证明：受限 publisher 分别在事务内 assembly/seal Agent、Flow、Instruction Skill、Strategy、Experience Release 及候选 Agent/Flow Deployment，登记依赖 manifest、closure、public-handle map 与 Run-pin registry；seal 后任何组成追加或改写都会失败。G1-A5 还必须证明 root 到 child 到 grandchild 的 join 拓扑可用，而 child 等于 parent 或 descendant 指向 ancestor 在 allocation/event/outbox 前被拒绝；Human Gate claim、并行 sibling quiescence 与 checkpoint/通知提交没有中间可见状态。G1-A6 还必须证明 immutable terminal billing snapshot 与 current billing state 分离；Run 接受事务保存 canonical 202 receipt；未终态 Run 的 key 永不释放，终态至少保留 24 小时 replay grace；取消/resume 的 mutation key 以固定 route 为唯一范围、target 在 intent hash 中，先命中历史 receipt 再做当前状态重验证。

上述夹具在 [Agent Release v1 与能力装配契约](./architecture/agent-release-v1与能力装配契约.md)、[五平台横向研究](./research/agent-platform-comparison-2026-08.md)、[Flow IR v1](./architecture/flow-ir-v1与运行时契约.md) 与 [SSE 契约](./api/SSE与异步操作契约.md) 中共享术语。G1-A1、G1-A3～G1-A6、G1-A8 按 L4 执行；G1-A2 与 G1-A7 按 L3 执行，但不得削弱共享 L4 安全约束。**G1 的 Agent 验收只在 G1-A1~G1-A8 全部通过后成立；随后才开始本节 P3 广度清单。** Mock 产品能力、定时/预设任务与通用任务推送属于后续 G2/P3；它们不占用 G1 编号，也不得用 mock 数据替代 G1-A8 的真实纵向证据。

## 10. 依赖图与重新估算规则

原 12 周甘特仅保留为功能规模参考，不能作为承诺排期。实际推进顺序为：

```text
文档冻结门（进入 G0-01）
  ↓
G0-08 可执行架构门
  ↓
S0a Closure/Policy/ResolvedPlan kernel
  ↓
S1a 最小 Flow ABI + 固定 Knowledge/只读 DB
  ↓
S2a Agent Strategy runtime + inert Skill activation
  ↓
G1 租户 + 发布版本 + 可恢复 Run + LLM/固定知识/只读 DB + SSE 闭环
  ↓
G2 Flow IR 核心节点 / 基础 RAG / 受控 HTTP 工具
  ↓
G3 画布广度 / 解析与多模态 / 插件生态 / 渠道 / 观测商业化
```

可以并行的工作只能在文件集合不重叠、依赖已满足且风险不高于 L2 时启动。`apps/studio` 壳、`parser-py` 或官方插件不得越过 G0/G1 的安全、版本与运行状态机前置条件。

## 11. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| flow-engine 语义复杂度被低估 | P1 延期拖垮全局 | S1/S2 spike 先冻结 IR；16 节点分三批交付（核心 6 → 逻辑 4 → 增强 6） |
