# 数据模型

Postgres 16 + pgvector + RLS。

> 设计冻结规则：除明确列出的全局只读系统目录外，所有客户业务、运行、引用、凭据元数据、审计和索引映射表必须直接带不可空的 `workspace_id`。租户上下文只在事务内存在，但不能信任调用方自行设置的 Workspace header 或 GUC：必须由受限认证函数验证 scoped credential 后建立带 transaction/session proof 的 `app.tenant_context`，`app.current_workspace_id()` 再校验该 proof。所有租户表启用并强制 RLS。前文中未带 `workspace_id` 的历史草图不可以直接生成迁移；本文件第 10 节和 ADR-003 优先。五平台研究新增的 Skill/Strategy/Experience/Deployment/Credential/HumanGate/Evaluation 规范以[Agent Release 契约](./architecture/agent-release-v1与能力装配契约.md)和本文件 §3.4/§10 为准；未回写到物理 migration 的旧 SQL 片段不得执行。

```
007  published_resource_versions / visibility / authorization_decisions / runs / parent links / flow_executions / attempts / steps / capability_calls / skill_activations / events / checkpoints / human_gates / mutation idempotency / outbox / credit facts / retention

```

`database/004-运行与计费.sql` 是“运行与计费”设计包编号，不是将来的物理 migration 编号；拆分落地时其中的 `published_resource_versions`、Run 与账务表属于逻辑第 007 段，必须排在 Agent/Flow/Plugin/Skill/A2A 的发布版本表之后。不得因为文件名为 004 而提前创建无法回读的裸版本 pin。

## 2. 工作空间与成员

```sql
create table workspaces (
  id uuid primary key,
  name text not null,
  plan text,
  credits_balance bigint not null default 0,    -- 当前可用积分，非负
  credits_reserved_balance bigint not null default 0, -- 已被 Run 预留，非负
  credits_balance_version bigint not null default 0,  -- reserve/settle/release 单调版本
  authorization_epoch bigint not null default 0,      -- Workspace 级授权状态真源；变更时原子递增
  expire_at timestamptz,
  created_at timestamptz default now()
);

-- 不保存原始 Workspace Access-Key。对外兼容头由 scoped credential 校验后映射。
create table api_credentials (
  id uuid primary key,
  workspace_id uuid not null references workspaces,
  key_id uuid not null unique,
  key_hint text not null,
  credential_kind text not null check (credential_kind in
    ('service_api','publish','webhook','mcp','permission_callback')),
  secret_verifier_hmac bytea not null,
  status text not null default 'active'
    check (status in ('active','overlap','revoked','expired')),
  not_before_at timestamptz,
  expires_at timestamptz,
  revoked_at timestamptz,
  rotation_group uuid,
  authorization_epoch bigint not null default 0,      -- 轮换/撤销/scope 修改时原子递增
  created_at timestamptz default now(),
  unique (workspace_id, id),
  unique (workspace_id, id, credential_kind),
  check (
    (status = 'active' and revoked_at is null)
    or (status = 'overlap' and revoked_at is null and expires_at is not null and rotation_group is not null)
    or (status = 'revoked' and revoked_at is not null)
    or (status = 'expired' and revoked_at is null and expires_at is not null)
  )
);
-- scope 与资源授权使用 api_credential_scopes、类型化 Agent/Flow entry grant
-- 或 SYSTEM-only internal grant；不在 JSON 中混入不可验证的资源 ID。
-- deployment_publish / agent_invoke / flow_invoke 是 OpenAPI operation purpose，
-- 不是凭据列或 profile 表。准入在同一事务联合 kind、scope、
-- 类型化 Deployment entry grant 和 target cardinality 派生决策，不建第二事实源。
-- 管理身份不是 api_credentials.credential_kind；它只能由已验证的
-- IdP/本地管理会话经短期 control attestation 建立，不能签发管理 API key。
-- secret_verifier_hmac 在数据库边界按 bearer-equivalent 处理：普通应用、
-- ba_runtime 与 ba_control_executor 均无整表 SELECT，只能读取显式列出的
-- 安全元数据列；验证材料只存在私有 auth projection 并由认证函数访问。

create table secret_refs (
  id uuid primary key,
  workspace_id uuid not null references workspaces,
  provider text not null,                   -- env | vault | k8s_secret | offline_bundle
  locator text not null,                    -- provider 内引用，不能是 secret 明文
  version_hint text,
  purpose text not null,
  status text not null default 'active',
  created_at timestamptz default now(),
  unique (workspace_id, provider, locator),
  unique (workspace_id, id)
);

create table workspace_members (
  workspace_id uuid not null references workspaces,
  user_id uuid not null,
  role text not null check (role in ('admin','developer','user','viewer')),  -- viewer = 仅查看
  role_config_id uuid,
  primary key (workspace_id, user_id)
);

create table role_configs (                     -- 2025-04-17 角色配置
  id uuid primary key, workspace_id uuid not null references workspaces,
  name text not null, permissions jsonb not null
);

create table permission_callbacks (
  id uuid primary key,
  workspace_id uuid not null references workspaces,
  endpoint_url text not null,
  credential_secret_ref_id uuid,

  failure_mode text not null default 'deny',
  status text not null default 'active',

create table authorization_policies (

    references permission_callbacks(workspace_id, id),

-- G0/G1 的 failure_mode 在 DB 层固定 deny；不存在 profile/approval 绕过。

create table service_principals (
  id uuid primary key,
  workspace_id uuid not null references workspaces(id),
  name text not null,
  purpose text not null check (purpose in ('scheduler','internal')),
  authorization_policy_id uuid not null,
  status text not null default 'active' check (status in ('active','revoked')),
  authorization_epoch bigint not null default 0,
  foreign key (workspace_id, authorization_policy_id)

-- Task 只能以这个受限服务主体进入授权流程；它不是用户凭据或可向 Prompt 注入的身份材料。

create table published_release_visibility (

create table api_credential_release_grants (
  id uuid not null,
  workspace_id uuid not null references workspaces(id),
  credential_id uuid not null,
  credential_kind text not null default 'service_api' check (credential_kind = 'service_api'),
  published_resource_version_id uuid not null,
  resource_kind text not null default 'SYSTEM' check (resource_kind = 'SYSTEM'),
  resource_id uuid not null,
  grant_state text not null default 'active' check (grant_state in ('active','revoked')),
  authorization_epoch bigint not null default 0,
  granted_at timestamptz not null default now(),
  revoked_at timestamptz,
  foreign key (workspace_id, credential_id, credential_kind)
    references api_credentials(workspace_id, id, credential_kind),
  foreign key (workspace_id, published_resource_version_id, resource_kind, resource_id)
    references published_resource_versions(workspace_id, id, resource_kind, resource_id),
  primary key (workspace_id, credential_id, published_resource_version_id),
  unique (workspace_id, id)
);
-- 本早期通用表在 §3.4 之后只服务内部 SYSTEM release；它不能表达 Agent/Flow
-- 公共入口、publish exchange 或依赖能力授权。Agent/Flow 公共入口只使用绑定稳定
-- deployment_id + channel/scope 的类型化 entry grant；内部 preview/test 使用受管理
-- 身份约束的独立授权路径，不复用本表或公共 credential。
-- 知识、数据库 operation、插件、Skill、A2A 等依赖资源分别使用其类型化 release/grant 表，
-- 不能回退到通用 resource_id 关联。

-- 历史 credits_ledger 草图已废止；实施必须采用 §10.3 / 004 的不可变
-- RESERVE / SETTLE / RELEASE 三角 delta 账本，不能以 balance_after 或日志替代。
```

## 3. Agent

早期 `agents + agent_versions + agent_skills + agent_knowledge` 草图把可编辑配置、已发布版本和多态资源 ID 混在一起，不能表达完整的 release pin、类型化执行器和跨 Workspace 完整性。该草图自本次冻结起仅作竞品字段索引，不能直接生成迁移。可执行语义以[Agent Release 契约](./architecture/agent-release-v1与能力装配契约.md)为准；下方既有 SQL 的 Agent/Experience/quick-entry/credential 部分若与 §3.4 冲突，以 §3.4 为准并必须在正式 migration 中替换，不能只加旁路表。

### 3.1 稳定身份、草稿与已发布 Release

```sql
create table agents (
  id uuid primary key,
  workspace_id uuid not null references workspaces(id),
  name text not null,
  icon text,
  visibility text not null default 'private',
  current_draft_revision_id uuid,
  current_published_release_id uuid,         -- 仅 Studio/authoring 指针；公开运行不得以此替代 Deployment
  tags text[] not null default '{}',
  deleted_at timestamptz,
  unique (workspace_id, id)
);

create table agent_draft_revisions (
  id uuid primary key,
  workspace_id uuid not null references workspaces(id),
  agent_id uuid not null,
  revision integer not null check (revision > 0),
  editor_spec jsonb not null,                -- UI 编辑状态；禁止存原始 secret/裸资源 ID 作为执行真源
  semantic_hash text not null,
  created_by uuid,
  created_at timestamptz not null default now(),
  foreign key (workspace_id, agent_id) references agents(workspace_id, id),
  unique (workspace_id, agent_id, revision),
  unique (workspace_id, id)
);

create table agent_releases (
  id uuid primary key,
  workspace_id uuid not null references workspaces(id),
  agent_id uuid not null,
  release_number integer not null check (release_number > 0),
  source_draft_revision_id uuid not null,
  state text not null check (state in ('published','archived','revoked')),
  role_spec jsonb not null,                  -- canonical role blocks / renderer version, 无资源裸引用
  input_contract jsonb not null,
  output_contract jsonb,
  model_policy_pin jsonb not null,            -- 只含 model alias/revision/contract hash；不含 key
  strategy_release_id uuid not null,          -- 类型化 FK 见 §3.4；不是通用 Tool/Prompt JSON
  authorization_policy_id uuid not null,
  runtime_limits jsonb not null,
  compiled_hash text not null,
  authorization_epoch bigint not null default 0,
  published_by uuid,
  published_at timestamptz not null default now(),
  foreign key (workspace_id, agent_id) references agents(workspace_id, id),
  foreign key (workspace_id, source_draft_revision_id)
    references agent_draft_revisions(workspace_id, id),
  foreign key (workspace_id, authorization_policy_id)
    references authorization_policies(workspace_id, id),
  unique (workspace_id, agent_id, release_number),
  unique (workspace_id, id)
);
-- Release 不存在 draft 状态；草稿保存与公开发布必须是两条不同路径。
-- agents.current_* 指针必须以同 Workspace 复合 FK/延迟约束指向上述表，避免跨租户别名。

-- Release 内容不可变；唯一受控状态机为 published -> archived/revoked，
-- archived -> revoked。任何状态/授权策略可见性收窄都必须成为 Decision 的
-- 可回读 epoch source，不能只靠调用方同时 revoke visibility/grant 的约定。
create or replace function app.bump_agent_release_epoch_before_write()
returns trigger
language plpgsql
security definer
set search_path = pg_catalog, public, app, pg_temp
as $function$
begin
  if tg_op = 'INSERT' then
    new.authorization_epoch := greatest(coalesce(new.authorization_epoch, 0), 1);
    return new;
  end if;

  if new.id is distinct from old.id
     or new.workspace_id is distinct from old.workspace_id
     or new.agent_id is distinct from old.agent_id
     or new.release_number is distinct from old.release_number
     or new.source_draft_revision_id is distinct from old.source_draft_revision_id
     or new.role_spec is distinct from old.role_spec
     or new.input_contract is distinct from old.input_contract
     or new.output_contract is distinct from old.output_contract
     or new.model_policy_pin is distinct from old.model_policy_pin
     or new.strategy_release_id is distinct from old.strategy_release_id
     or new.authorization_policy_id is distinct from old.authorization_policy_id
     or new.runtime_limits is distinct from old.runtime_limits
     or new.compiled_hash is distinct from old.compiled_hash
     or new.published_by is distinct from old.published_by
     or new.published_at is distinct from old.published_at then
    raise exception 'agent release content and identity are immutable; publish a new release'
      using errcode = '23514';
  end if;

  if new.state is distinct from old.state then
    if not (
      (old.state = 'published' and new.state in ('archived','revoked'))
      or (old.state = 'archived' and new.state = 'revoked')
    ) then
      raise exception 'invalid agent release lifecycle transition'
        using errcode = '23514';
    end if;
    new.authorization_epoch := old.authorization_epoch + 1;
  elsif new.authorization_epoch is distinct from old.authorization_epoch then
    raise exception 'agent release authorization_epoch is maintained only by lifecycle mutation'
      using errcode = '42501';
  end if;
  return new;
end;
$function$;

create or replace function app.record_agent_release_epoch_after_write()
returns trigger
language plpgsql
security definer
set search_path = pg_catalog, public, app, auth, pg_temp
as $function$
begin
  if tg_op = 'INSERT' or new.authorization_epoch is distinct from old.authorization_epoch then
    perform auth.record_authorization_epoch_change(
      new.workspace_id, 'agent_release', new.id, '', new.authorization_epoch
    );
  end if;
  return null;
end;
$function$;

create trigger agent_releases_epoch_before_write
before insert or update on agent_releases
for each row execute function app.bump_agent_release_epoch_before_write();
create trigger agent_releases_epoch_after_write
after insert or update on agent_releases
for each row execute function app.record_agent_release_epoch_after_write();
create trigger agent_releases_reject_delete
before delete on agent_releases
for each row execute function auth.reject_authorization_source_delete();
```

`agent_releases` 是可执行真源，并在同一发布事务登记为 `published_resource_versions` 的 `AGENT` 资源版本；只有 `state='published'` 的 Release 可创建新的 Authorization Decision/Run，`archived`/`revoked` 必须使同一 source 集的后续 Call 被拒绝。`editor_spec` 可保留纯展示/编辑数据，但所有可执行资源关系必须由以下规范化绑定表表达；Release 上的 canonical JSON 只能用于审计/编译复现，并由 hash 与关联表一致性校验约束。

### 3.2 通用 Binding 与按类型扩展

```sql
create table agent_release_capability_bindings (
  id uuid primary key,
  workspace_id uuid not null references workspaces(id),
  agent_release_id uuid not null,
  binding_key text not null,                 -- Release 内稳定、可用于审计与快捷入口
  kind text not null check (kind in
    ('knowledge','database','flow','plugin','skill_pack','subagent')),
  enabled boolean not null default true,
  discoverability text not null check (discoverability in
    ('model_selectable','forced','hidden')),
  manual_description text not null,
  input_description text,
  manual_hash text not null,
  input_schema jsonb not null,
  output_schema jsonb,
  input_interaction_mode text not null default 'auto'
    check (input_interaction_mode in ('auto','form')),
  output_handling_mode text not null default 'model_summarize'
    check (output_handling_mode in ('model_summarize','raw','structured')),
  data_classification text not null,
  side_effect_class text not null check (side_effect_class in
    ('safe','requires_key','unsafe')),
  task_safe boolean not null default false,
  mock_safe boolean not null default false,
  retry_policy jsonb not null,
  timeout_ms integer not null check (timeout_ms > 0),
  budget jsonb not null,
  sort integer not null default 0,
  foreign key (workspace_id, agent_release_id)
    references agent_releases(workspace_id, id),
  check (not task_safe or kind in ('flow','plugin')),
  check (not mock_safe or (kind <> 'database' and side_effect_class = 'safe')),
  unique (workspace_id, agent_release_id, binding_key),
  unique (workspace_id, agent_release_id, id),
  unique (workspace_id, id)
);

-- 发布不是“先发 Release，之后再慢慢补 Binding”的可观察过程。发布器先创建一条
-- 仅在本事务有效的 assembly gate；gate 的随机 nonce 只在
-- app.publish_agent_release() SECURITY DEFINER 内通过 SET LOCAL 暴露，表内只保存
-- SHA-256。所有可执行装配物都必须带同一 agent_release_id，并在 gate=assembling
-- 时插入；发布器在完整性校验、compiled_hash 比对与 registry 登记都成功后才 seal。
create table agent_release_publish_assemblies (
  workspace_id uuid not null references workspaces(id),
  agent_release_id uuid not null,
  assembly_token_hash text not null check (assembly_token_hash ~ '^[0-9a-f]{64}$'),
  state text not null check (state in ('assembling','sealed')),
  sealed_at timestamptz,
  sealed_by uuid,
  created_at timestamptz not null default now(),
  primary key (workspace_id, agent_release_id),
  foreign key (workspace_id, agent_release_id)
    references agent_releases(workspace_id, id),
  check (
    (state = 'assembling' and sealed_at is null and sealed_by is null)
    or (state = 'sealed' and sealed_at is not null and sealed_by is not null)
  )
);

create or replace function app.require_open_agent_release_assembly()
returns trigger
language plpgsql
security definer
set search_path = pg_catalog, public, app, pg_temp
as $function$
declare
  v_token text;
  v_token_hash text;
  v_state text;
begin
  v_token := current_setting('app.agent_release_assembly_token', true);
  select assembly_token_hash, state
    into v_token_hash, v_state
    from agent_release_publish_assemblies
   where workspace_id = new.workspace_id
     and agent_release_id = new.agent_release_id
   for key share;

  if not found
     or v_state <> 'assembling'
     or v_token is null
     or encode(digest(v_token, 'sha256'), 'hex') <> v_token_hash then
    raise exception 'agent release material may be inserted only by the open publish assembly'
      using errcode = '42501';
  end if;
  return new;
end;
$function$;

-- Typed binding tables carry binding_id rather than repeating agent_release_id.
-- Resolve the owning Release under lock before applying the same assembly gate.
create or replace function app.require_open_agent_release_binding_assembly()
returns trigger
language plpgsql
security definer
set search_path = pg_catalog, public, app, pg_temp
as $function$
declare
  v_release_id uuid;
  v_token text;
  v_token_hash text;
  v_state text;
begin
  select agent_release_id
    into v_release_id
    from agent_release_capability_bindings
   where workspace_id = new.workspace_id
     and id = new.binding_id
   for key share;
  if not found then
    raise exception 'typed binding has no owning agent release binding'
      using errcode = '23514';
  end if;

  v_token := current_setting('app.agent_release_assembly_token', true);
  select assembly_token_hash, state
    into v_token_hash, v_state
    from agent_release_publish_assemblies
   where workspace_id = new.workspace_id
     and agent_release_id = v_release_id
   for key share;
  if not found
     or v_state <> 'assembling'
     or v_token is null
     or encode(digest(v_token, 'sha256'), 'hex') <> v_token_hash then
    raise exception 'typed binding may be inserted only by the open publish assembly'
      using errcode = '42501';
  end if;
  return new;
end;
$function$;

create or replace function app.prevent_agent_release_assembly_reopen()
returns trigger
language plpgsql
security definer
set search_path = pg_catalog, public, app, pg_temp
as $function$
declare
  v_token text;
begin
  if tg_op = 'DELETE' then
    raise exception 'publish assembly cannot be deleted'
      using errcode = '55000';
  end if;
  if old.state = 'assembling'
     and new.state = 'sealed'
     and new.workspace_id is not distinct from old.workspace_id
     and new.agent_release_id is not distinct from old.agent_release_id
     and new.assembly_token_hash is not distinct from old.assembly_token_hash
     and new.created_at is not distinct from old.created_at
     and new.sealed_at is not null
     and new.sealed_by is not null then
    v_token := current_setting('app.agent_release_assembly_token', true);
    if v_token is not null
       and encode(digest(v_token, 'sha256'), 'hex') = old.assembly_token_hash then

  end if;

    using errcode = '55000';
end;
```

通用表**不得**以 `target_type + target_id` 伪造外键。每种 Binding 使用一个同 Workspace 的类型表，类型表的存在与 `kind` 一致性由约束触发器或发布器的不可变校验保证：

| 类型表 | 必须 pin / 约束 | 关键本地策略 |
|---|---|---|
| `agent_release_knowledge_bindings` | `knowledge_base_id`、可检索 KB/index release、retrieval/rerank contract hash | `on_demand` / `force` / `disabled`、metadata filter、最大结果、引用输出与空结果降级 |
| `agent_release_database_bindings` | connector、不可变 `database_operation_release`、精确 table revision | 表/列/行 allowlist、参数/结果 schema、最大行数、只读或单次写、审批、operation key；默认只读 |
| `agent_release_flow_bindings` | 已发布 `flow_version_id`、输入/输出 contract hash | 同步为嵌套 `FlowExecution`；异步为 child Run，均有取消传播与预算切分；Agent 只能进一步收紧 Flow 策略 |
| `agent_release_plugin_bindings` | plugin/MCP provider/tool release、transport/endpoint identity、tool-list/schema hash、`credential_requirement_id` | 默认参数、出网/认证需求、副作用、幂等操作键；实际 credential 在 Deployment/Run 解析，不存 secret 明文 |
| `agent_release_skill_pack_bindings` | skill pack release 及其展开后的 Binding 清单 hash | 只作为本项目扩展；升级不得修改既有 Agent Release |
| `agent_release_subagent_bindings` | `target_agent_release_id` 或已发布外部 A2A contract | 同步/异步、上下文投影、input allowlist、最大深度/调用数、预算份额、授权委托模式 |

每一个类型表都以 `(workspace_id, binding_id)` 引用通用 Binding，并以 `(workspace_id, resource_id, revision_id)` 或等价复合 FK 引用其目标。发布器还必须验证类型表与通用行的 `kind` 一致。`task_safe=true` 是已发布 Binding 的不可变字段，且只允许 Flow/Plugin；`mock_safe=true` 只允许无真实副作用、非数据库 Binding。Task、Mock 必须以三列 `(workspace_id, agent_release_id, binding_id)` 回指同一个 Release，不能跨 Release 拼接；快捷入口按 §3.4 归 Experience Release，并在 Deployment 装配时校验。**G0/G1 只有 sealed pinned dependency closure：当前 schema 根本不存在 binding mode、compatibility approval 或 floating publish audit 表/列。**未来若有 compatibility envelope，必须以新 schema version、独立 ADR 和新 sealed-closure 验收门引入，不能回填或曲解当前 Release。对全局只读官方插件的例外必须在类型表中带目录 release ID 和明确豁免理由，不能把租户 secret 或配置放进全局表。

发布器是唯一写入 Agent Release、assembly gate、Strategy pin、Instruction Skill refs、Binding、类型表、Task/Mock、publish audit、dependency manifest 和不可变 Run-pin registry 的入口：它以受认证的控制面 Workspace context 开始事务，创建随机 nonce 和 assembling gate，写齐所有发布物，验证每个 Binding 恰有匹配类型行、所有 pin/approval/Task/Mock 引用、canonical content 与 compiled hash，再登记 registry 并把 gate 置为 sealed。Experience/Deployment 使用各自 publisher/assembly，不得借 Agent publisher 跨生命周期追加 UI 或 credential mapping。普通 runtime/control 应用角色没有这些表的原始 INSERT/UPDATE/DELETE 权限；只能执行已审阅、SECURITY DEFINER 的发布器。历史 Release 迁移时必须先回填一行 sealed gate（含迁移审计）再启用 gate trigger；不得为兼容目的给已发布 Release 追加 Binding 或 audit。

`agent_release_task_templates` 不得仅因 `binding_id` 属于通用表就执行任意类型；三列复合 FK 加上 `agent_release_task_template_reference_safety` 延迟约束触发器，在插入和更新时强制首版只引用同一 Release、`task_safe=true` 的 Flow/Plugin Binding。`agent_release_capability_bindings_immutable` 则禁止 Release 组装提交后 UPDATE/DELETE Binding，防止既有 Task/Mock 被反向降级为不安全。任务 Run 固定模板、Agent Release、Binding pin、受限服务主体、输入摘要和 idempotency namespace；每次实际副作用前仍检查撤销/有效期。

Mock fixture 只允许 preview 或批量调试上下文，不能用于公开发布、数据库 Binding 或真实副作用的静默短路。`agent_release_mock_fixture_reference_safety` 在插入和更新时要求 `mock_safe=true`、非 database 且 `side_effect_class='safe'`；执行器还必须把 `simulation=true` 作为硬 gate：生产/公开 Run 不能读取 fixture，预览/批调 Run 也不得把 fixture 作为真实数据库或外部副作用的回退。快捷入口由 `experience_release_quick_entries` 以公开 handle/schema 表达，Deployment 组装时解析到目标 Agent Release；触发 Binding 时仍走完整授权和 Plan。隐藏技能名称/图标只影响投影，不删除绑定和 Run 审计。

`authorization_decisions` 保存脱敏、不可变的授权证据，而不是原始权限 SPI 响应。`subject_kind`、nullable credential 复合 FK、service principal 复合 FK、policy/callback 复合 FK 使用户、匿名和任务主体的来源可验证；任务决策必须记录实际 `service_principal_id`，不能仅把它埋入字符串或 JSON。`app.create_authorization_decision` 还必须验证 policy 属于该 Agent Release、callback 属于该 policy（如有）、service principal 属于该 policy（如有）。`authorization_decision_epoch_sources` 才是多源 vector 的权威集合，`authorization_epoch_vector` 只是由其排序生成的响应/调试投影。该函数必须在同一 RLS 事务逐类型锁定并写入 Workspace、实际 credential（如有）、callback/policy、实际 service principal（如有）、**Agent Release 自身**、稳定 Deployment 与对应类型化 Agent/Flow entry grant（SYSTEM 路径才可用 internal SYSTEM grant）、顶层 visibility 及每个允许 Binding 的 release/grant source。禁止应用角色直接插入或修改 Decision/source 行。每个 Call 重新读取**同一 source 集合**的当前 epoch，而不是猜测 JSON 字段；过期由 `expires_at` 和当前时钟派生，不回写篡改原 decision。Run/Capability Call 关联其 ID。恢复/高风险调用按 Agent Release 契约重新检查撤销，重新授权只能收窄而不能扩张已接受 Run 的可用 Binding。

`agent_releases`、`authorization_policies`、`service_principals`、各类型 release/grant、顶层 visibility、Agent/Flow entry grant 与 internal SYSTEM grant 的 INSERT、授权相关 UPDATE、archive/revoke 必须复用 `auth.record_authorization_epoch_change` 的同事务路径：先单调递增自身 `authorization_epoch`，再递增 Workspace epoch、追加 `authorization_cache_invalidations` 并发送仅作加速的通知；`agent_release` 与类型化 release source 必须能被同一 source resolver 精确回读。Release 内容、Binding 内容，以及授权 source 的稳定身份/关联键（`id`、`workspace_id`、credential 的 `key_id`/`credential_kind`、visibility/typed grant 的 credential/deployment/release 键）一律不可 UPDATE；变更采用 revoke/归档后新建行，不能静默换绑。直接 DELETE 一律拒绝，以 revoked/disabled 状态替代。正式 Agent migration 必须为每张上述表附加相同的 before/after 触发器或仅暴露等价的 `SECURITY DEFINER` 变更函数，且撤销 `ba_runtime` 的直接 DML 权限。

| `credential_requirements` | Agent Release + Binding、provider、audience、最小 scopes、允许 principal modes | Release 只声明需求；无需求的 Binding 不伪造 `none` mapping。 |
| `deployment_policy_versions` / `deployment_credential_mappings` | Workspace-scoped immutable typed policy pin（policy kind/id/version/contract hash）、caller delegated/service principal/team shared 判别形状、Deployment revision与 requirement | G0 mapping 的 provider/audience逐字一致，allowed scopes与 required scopes集合精确相等；不得存 secret value、裸 policy text ID或把 delegated 缺失回退为共享凭据。 |
| `deployment_promotion_records` | from/to revision、diff/evaluation evidence、actor/approver、decision/time | production promotion/rollback 是可审计 mutation；失败评测或缺审批不得激活。 |

G0-05 不创建独立 `admission_profiles` 或假 `runs` 表。Agent/Flow direct resolver只在锁定 credential/typed grant/distinct stable target/active pointer/security state的事务中返回 closed `*DeploymentEntryAdmissionSnapshotV1` DTO；它保存 literal entry tuple、full release pins、activation audit epoch、observed revoke epoch和Workspace/credential/grant/policy/mapping/dependency hash，不含Run、resolved credential、closure meet或effective policy。G0-06在创建Run/reservation/outbox的同一事务持久化该snapshot；G1-01再生成effective AdmissionProfile/ResolvedPlan。

正式 schema 还必须满足：

1. `agent_releases.strategy_release_id` 以 `(workspace_id,strategy_release_id)` 引用 published Strategy Release；发布 assembly 同时 seal Strategy pin、Instruction Skill refs、Capability Binding、Task/Mock 和 dependency manifest。
2. `experience_spec` 从 `agent_releases` 删除，`agent_release_quick_entries` 迁移为 `experience_release_quick_entries`；历史数据要生成独立 Experience Release 和 Deployment revision 后才能启用公开入口。
3. Plugin/MCP Binding 只保存 provider/tool/transport/schema hash 和 `credential_requirement_id`。底层 credential policy 可以引用 `secret_refs` 的 locator，但 Agent Release、Skill、Strategy、Experience、Deployment JSON 均不持有 raw secret 或用户 token。
4. `authorization_decisions` 新增同 Workspace 的 `deployment_revision_id`、`experience_release_id`、实际 credential binding/policy refs 与 `credential_snapshot_hash`；准入 Decision 记录 active pointer 的 observed activation epoch 作为“如何解析 revision”的审计证据，但已接受 Run 的逐 Call 重验证集合**不含 active pointer**，只含稳定 Deployment revocation/status、固定 revision/Release/resource/grant/policy/实际 credential epoch。Decision 不能只靠 `agent_release_id + api_credentials.credential_id` 表达最终用户委托。
5. API publish credential/grant 绑定稳定 `deployment_id + channel/scope`，而不是 Deployment revision 或任意 Agent Release。兼容 `robot_id/agentId` 只与 credential 一起解析唯一稳定 Deployment；准入事务读取唯一 active pointer 并固定 revision，客户端不能指定 revision。若未来引入 revision-specific preview token，必须使用独立 credential kind 与内部路由。
6. 以上 release/revision 表均纳入 `published_resource_versions` 或等价类型化 registry、RLS、不可变 lifecycle trigger、authorization epoch 和 retention；在这些约束补齐前 §3.1~§3.3 的 SQL 只是迁移输入，不是可执行完成态。
7. `PublishedResourceKind` 至少覆盖 `AGENT_RELEASE`、`FLOW_VERSION`、`SYSTEM_RELEASE`、`KNOWLEDGE_INDEX_GENERATION`、`DATABASE_OPERATION_RELEASE`、`PLUGIN_TOOL_RELEASE`、`SKILL_PACK_RELEASE`、`A2A_AGENT_RELEASE`、`INSTRUCTION_SKILL_RELEASE`、`AGENT_STRATEGY_RELEASE`、`EXPERIENCE_RELEASE`、`DEPLOYMENT_REVISION`。`BindingKind` 仅为 knowledge/database/flow/plugin/skill_pack/subagent，并以判别式 FK 映射到允许的 resource kind；Skill/Strategy/Experience/Deployment 不伪装为 Capability Binding。

一个 Conversation 可以跨 Agent Release，但 G1 只允许在 `conversation_contract_hash` 不变时跨版本。该 hash 由 canonical 的会话输入变量 schema、允许的 `session_store` key/value schema 与 history/context serialization ABI 计算；它不包含 Prompt 文案、模型或资源 pin。受控 Conversation 创建函数在同一事务锁定 active pointer，验证 revision 与稳定 Deployment 的复合关系、校验初始变量并从该 revision 复制 hash；应用角色不得原始 INSERT 或改写这些 pin。每个首次 Chat 准入在创建 Run、reservation 或 outbox 前比较当前 active revision 的 hash，不相等则返回 `409 CONVERSATION_REVISION_INCOMPATIBLE` 并要求新建 Conversation，绝不自动改写 `variables`、`session_store` 或历史消息。命中既有幂等 Run 仍回放原 acceptance receipt，不重新解析 active revision。每个用户消息/助手回复和对应 Run 才是执行版本边界；恢复、计费、授权和能力调用以 Run/Capability Call 为准，`messages.tasks` 只能保存已脱敏的兼容投影，不能作为资源 pin 或权限事实源。

## 10. 设计冻结补充：迁移与隔离真源

本节优先于上文为竞品功能而写的早期表草图。实施时不得以 `run_logs`、JSON 资源引用或应用层约定替代这里的约束。

可评审 SQL 草案：[001-租户与凭据](./database/001-租户与凭据.sql) 与 [004-运行与计费](./database/004-运行与计费.sql)。两者均未执行；进入实现前必须以仓库的 migration 框架拆分、审查并在目标 Postgres 版本上验证。

### 10.1 租户不变量与 RLS

1. 所有客户数据表都直接拥有 `workspace_id uuid not null`；官方插件等全局目录必须只读，并在迁移清单中说明豁免理由。
2. 父子资源采用 `unique (workspace_id, id)` 与复合外键，阻止子记录、发布版本、工具绑定和会话跨 Workspace 指向父记录。
3. 多态 `target_type + target_id`、JSON 内资源 ID 或动态物理表名不得仅靠应用代码校验；应拆成关联表或由约束触发器验证同租户。
4. 每张租户表执行 `ENABLE ROW LEVEL SECURITY` 与 `FORCE ROW LEVEL SECURITY`；API 和 Worker 只有在受限认证函数验证凭据后才拥有本次事务的租户上下文，提交/回滚后自动清除。

示意 policy（实际 migration 必须为每张表生成并测试）：

```sql
-- 001 中 app.current_workspace_id() 是 SECURITY DEFINER helper：它验证
-- credential-bound、session-bound、transaction-bound proof，失败返回 NULL。
-- 调用方自行 SET app.workspace_id 不会影响此结果。
alter table agents enable row level security;
alter table agents force row level security;
create policy agents_workspace_isolation on agents
  using (workspace_id = app.current_workspace_id())
  with check (workspace_id = app.current_workspace_id());
```

认证前查询使用独立的最小 `auth.credential_auth_index` 投影：`ba_runtime`、`ba_control_executor`、admission/metering/finalizer/reconciliation executors 和普通应用角色没有其表权限；仅 `ba_auth_owner` 所有的 `auth.authenticate_api_credential(key_id, presented_verifier)` 可以读取。`api_credentials.secret_verifier_hmac` 与 presented verifier 在 DB 边界都是 bearer-equivalent，因此上述角色对 `api_credentials` 的整表 `SELECT` 也必须显式撤销，只按列 grant 非 verifier 的安全元数据。认证先按不可猜测 key ID 定位，再只用私有 `auth.constant_time_equal_32` 比较固定 32-byte verifier；普通 equality 不满足契约。presented verifier 只能是 binary-bound never-log 参数，生产必须读回 PostgreSQL 两项 parameter-log 上限均为 0，并验证 pooler/APM/error/support export 无参数采集，否则 fail-closed。认证函数只返回 `workspace_id`、`credential_id`、`credential_kind`，并设置经凭据 verifier、`session_user`、当前 transaction 绑定的 `app.tenant_context`；不返回原始 secret、verifier、scope、资源授权或用户数据。认证成功后才以 RLS 查询 scope/资源授权。连接池 checkout、事务回滚、凭据撤销和后台投影必须测试该 proof 不可跨事务、跨 session 或跨 Workspace 复用。

内部 admission、metering、finalizer、reconciliation 阶段不得拿任意客户或外部 `api_credentials` 建立 RLS context。它们只能使用受信部署控制面签发、最长 15 分钟、同时绑定 `workspace_id + session_user + exact service_phase` 的 `auth.internal_service_attestations`；wrong-phase、过期、撤销、跨连接或跨事务 proof 必须返回无 context。该 context 不产生外部 API principal，也不能读取 principal-scoped Run。

### 10.2 凭据、secret 与发布版本

- `api_credentials.secret_verifier_hmac` 是唯一可持久化的凭据验证材料，但在 DB 权限边界按 bearer-equivalent 秘密处理；认证 projection 只复制 verifier 及必要状态，仅 `ba_auth_owner` 可读，原始值只在创建/轮换响应中展示一次。`ba_runtime`/`ba_control_executor`/admission/metering/finalizer/reconciliation executors 对基表的 `SELECT *` 和 verifier 列读取必须失败，只允许显式安全列 grant。凭据 lifecycle 单向：进入 `overlap` 时必须有同一 rotation group 和服务端限定、不超过 24 小时的过期时间；rotation group 一经写入不可改，overlap 之后不得回到 active 或延长期限；revoked/expired 永不回活，认证拒绝无期限或无 rotation group 的 overlap。G0/G1 的 Webhook/MCP 也只允许 header/mTLS/安全配置，不存在 query/path secret、legacy 开关或 dormant compatibility 字段；future 需求必须新建独立 sealed safety envelope/schema/migration/gate。
- `secret_refs` 指向部署画像中的 secret provider，不在 `flow_env_vars.value`、Flow IR/Release、`custom_plugins.auth_config`、日志、SSE 或 trace 中保存原文。Flow/Plugin 发布物只声明 `CredentialRequirement`；实际 secret handle 由入口/Deployment mapping 与可信主体在 Run Plan 中解析。
- `agents` 是稳定业务身份；`agent_draft_revisions` 是仅供编辑/预览的真源；`agent_releases` 是不可变执行装配；Instruction Skill、Strategy、Experience 各自具备只追加 Draft revision 与不可变 Release，Deployment 具备不可变 revision。公开入口 grant 绑定稳定 `deployment_id + channel/scope`；接受事务原子解析独立 active pointer，再固定 Deployment revision 与 Agent/Experience Release。顶层 Flow/System 保持各自 release pin。`published_resource_versions` 或等价 registry 必须覆盖这些可发布类型及其依赖 manifest。`runs` 仍以判别 target pin 验证实际 Agent/Flow/System 执行目标，Agent Plan 另以复合 FK 固定 `deployment_revision_id + agent_release_id + experience_release_id`；不能接受裸 UUID、错误组合或跨 Workspace pin。
- `agent_release_capability_bindings` 只保存通用执行行为字段；目标资源由按类型关联表引用。Instruction Skill/Strategy 分别使用非 Capability release/ref 表，`skill_pack` 只展开已建模 Capability。数据库、知识、Flow、插件/MCP、`skill_pack` 和 SubAgent 不能依赖 `target_type + target_id` 或 JSON 内 ID 作为可执行真源。G0/G1 的类型化 FK、dependency manifest 和 sealed assembly 只允许完整 pinned closure，当前 schema 不建模任何 floating/兼容绕过。发布后任何组成不可 UPDATE/DELETE；实际运行解析仍须写入 Plan/Call/Skill activation。
- `authorization_decisions` 保存 Deployment/Agent/Experience、脱敏策略版本、可验证 subject/credential binding、允许 Binding hash、有效期与 epoch vector。准入记录 active pointer observed epoch 仅用于证明 revision 的解析来源；逐 Call 权威 source 集至少包含 Workspace、稳定 Deployment revocation/status、固定 Deployment revision/entry grant、Agent/Experience Release、实际 credential 及其 mapping、permission callback/policy、任务 service principal、每条获准类型资源 release/grant，**不包含 active pointer activation epoch**。promotion/rollback 因而不影响已接受 Run；其他撤销/状态/scope/grant 变化只能收窄或拒绝。G0/G1 没有 floating source 或 approval；未来只能在独立 sealed envelope 中新增 source kind。
- 对外 `Access-Key`、Webhook/MCP token、短期 browser session token 和管理身份分别具备 scope、Deployment/资源绑定、过期、撤销和审计。`CredentialOperationPolicyV1.operation_purpose` 是 OpenAPI 路由标签，不是持久化授权源；其结果只能由 kind + scope + Agent/Flow 类型化 entry grant + target cardinality 联合派生。browser session 只能经 exchange-only publish credential + host verified user 取得；SDK `user.id` 不建立 principal。用户 delegated credential、任务 service principal 和 team shared credential 不得互相回退；详见 ADR-003 与 Agent Release §6.2。

### 10.3 持久化运行与计费

以下实体是执行和计费事务事实源，完整状态机见 ADR-004：

| 表 | 关键唯一性/约束 | 用途 |
|---|---|---|
| `runs` | operation/route/key+intent/receipt/principal/Plan/target+dependency+input pins/accepted output schema ref+hash/billing owner/accepted_at 插入后全部不可改；`status` 逐字使用内部共享 RunStatusV1（含 WAITING/RESUMING/NEEDS_ATTENTION）并由 `termination_reason` fail-closed 映射；keyed Run 在全部非终态始终 active，终态后至少保留 `finished_at + 24h`；immutable result-or-error/`terminal_billing_pending`/terminal event id+sequence 墓碑与 mutable `billing_state` 分列；events/recovery 保留窗口分列；当前 004 基线只允许 self-owned top-level | 顶层用户、Webhook、调度或内部触发的执行意图、稳定受理重放、终态公共快照/墓碑与当前结算状态 |

`database/004-运行与计费.sql` 当前只冻结了通用 Run/Attempt/Step/Event/账务基线，尚未包含本节的 Agent、Deployment/Credential、Instruction Skill activation、HumanGate/resume 专属扩展；因此不能把它报告为已支持 Agent Release 运行或耐久 HITL。实施 Agent 迁移时必须新增下列规范化记录，并与既有 Run 事务、RLS 和 retention 同步落地：

以上 child/link/allocation 记录是已接受的目标形状，不是当前 004 基线已开放的写路径。当前基线固定 `runs.run_kind='top_level' + billing_owner_run_id=id`，拒绝所有 parent-link INSERT，并对任何已有 link 的取消 fail closed。后续专属 migration 必须在同一版本原子建立受控 allocation 函数、deferred exactly-one 约束与父取消 cascade intent/outbox，完成后才可开放 child CHECK；应用不得用多步写入模拟。

启用后，这些记录必须使用 `(workspace_id, run_id)`、`(workspace_id, agent_release_id)`、`(workspace_id, binding_id)` 和 `(workspace_id, authorization_decision_id)` 的复合 FK；父 `call_id` 也必须属于同一 Run。`run_kind='child'` 时它必须有且只有一个 `run_parent_link`，并与**直接父 Run 共享同一个根** `billing_owner_run_id`，绝不能写成 `parent_run_id`。`app.assert_agent_child_budget_topology` 是 `DEFERRABLE INITIALLY DEFERRED` 约束触发器：它锁定 child、direct parent 与 billing owner，验证 owner 是 top-level、自身 owner、link 与 allocation 的四元键一致，并拒绝 child 已有 `credit_reservation` 或顶层 Run 被作为 child link。`allocate_child_budget` 只在同一事务锁定 billing-owner reservation 后写 child Run、link、allocation、初始 Event/Outbox；`reserve_credits` 只接受 self-owned top-level Run，parent-link 插入也拒绝已有 reservation。`agent_charge_attributions` 中无 allocation 的计量只能满足 `metered_run_id=billing_owner_run_id`；有 allocation 的计量必须以候选键把 `metered_run_id` 对应到 allocation 的 `child_run_id`，并共享该根 owner。`credits_ledger.run_id` 始终保留 billing owner，child Step/Call 不得硬塞进它。完整的 Resource Pin/Plan 可存受控对象引用并用 hash 校验，不能以可变 JSON 或裸 UUID 代替。同步 Flow/SubAgent 分别通过 `flow_executions` / `agent_executions` 表达：二者复用 root Run，但固定自己的 execution ID、release pin/subplan/delegation hash、scope 和 checkpoint；异步调用才通过 `run_parent_links` 创建 child Run。三者都不应创建第二个账务或事件事实源。

`Idempotency-Key` 可以为空；为空时不承诺服务端去重。提供时，`accepted_at + 24h` 只是初始重放期的**下界**，不是非终态 Run 的自动失效时刻：key 在 QUEUED/RUNNING/CANCEL_REQUESTED/长期 WAITING/RESUMING 全部期间必须保持 `idempotency_active=true`；Run 终态时把重放期单调扩展至不早于 `finished_at + 24h`，之后仅受控 retention expiry 函数可置 false。同 key + 同稳定 `intent_hash` 返回同一 Run，不同 intent 返回冲突。数据库触发器在 INSERT 后冻结 operation/route/key+intent/canonical receipt/principal/`accepted_plan_hash`/target pins/dependency pins/input refs+hash+redacted summary/root billing owner/`accepted_at`；唯一允许的幂等字段变更是受控的单调 expiry 扩展与宽限期后停用。`intent_hash` 必须按 [SSE 契约 §2.4](./api/SSE与异步操作契约.md#24-intent_hash-的-canonical-编码) 的 RFC 8785/JCS preimage 计算，不含 credential binding、已解析 target/release、authorization decision、resource pin 或 Plan；首次已固定的执行事实另以 `accepted_plan_hash` 保存。Run 接受事务同时保存 `acceptance_receipt_http_status=202` 与严格限字段的 `acceptance_receipt_data_redacted`；幂等重放只重用这部分稳定 Operation data，当前 HTTP exchange 的 `request_id`/`now_time` 每次重新生成。每次 HTTP 请求的 `request_id` 属于 transport/audit 层，幂等重放不得覆盖 `runs.accepted_request_id`；SSE projector 以 `(workspace_id, run_id)` 关联 `runs` 读取该 accepted identity，不在每条 `run_events` 冗余存 transport request id。

取消与 Human Gate resume 使用 `run_mutation_idempotency`，不复用 Run 创建键。唯一范围固定为 `(workspace, principal, route template, key)`；target Run/Gate 位于 JCS intent，因此同 key 跨目标复用返回 409。取消函数不接受调用方 opaque hash：数据库只为该固定 scalar-only preimage 由 `cancel_intent_hash_v1(run_id)` 构造 RFC 8785/JCS 字节并哈希，命中后仍独立比较保存 target 与本次 target；通用 JSON JCS 必须由版本锁定的可信 canonicalizer 提供，不能用 `jsonb::text`。Mutation 行的身份、intent 和首次响应插入后不可改，并且在目标 Run 全部非终态（包括任意时长 WAITING）保持 active；只有目标终态且 `finished_at + 24h` 已过的受控 retention 函数才可停用/删除，单纯超过初始 `idempotency_expires_at` 不停用 key。Resume 的 preimage 固定为 route template、schema version、run/gate、action 和规范化 input；principal 只能来自 transaction context。只有幂等 miss 才锁定 Gate/Run/barrier，并在同一事务写 claim/decision、重新授权结果、mutation 和封闭 outcome receipt：中间 cohort 的正向 decision 只物化下一 Gate 与 `run.waiting`，不创建 attempt/outbox；最后一个正向 decision 才写 `run.resumed`、新 attempt 与恢复 outbox；reject/expire 只写 terminal intent 并唤醒唯一 finalizer。相同 key/hash 只重放首次 canonical receipt，不重验当前 Gate。并发 decision 通过 pending-only 条件更新和唯一 terminal decision 约束保证单一胜者；过期、actor 无权、operation hash/epoch 变化均不得产生下一 attempt。

进入等待采用两段、同一 barrier generation 的受控事务。candidate Worker 先在同一个 Run/barrier CAS 中建立 `DRAINING` barrier、冻结全图新调度和 frontier、提交 checkpoint，并把自己的可执行 lease 原子标为 `RELINQUISHED`、handoff 给不能执行业务动作的 host-only barrier owner；任一步失败整体回滚。host drain/checkpoint sibling，证明 active executable lease、待 dispatch outbox 和未对账 attempt 全部为零后，才在 waiting 事务递增 execution fence、写 Step=`SUSPENDED`、pending HumanGate、Run=`WAITING_FOR_INPUT|WAITING_FOR_APPROVAL`、`run.waiting` event 与通知 outbox，并释放 barrier owner。candidate lease 不能等到 WAITING 后再释放；barrier owner 不计入 executable lease。普通 queue/recovery claim 必须排除 WAITING Run；只有最后一个正向 Gate decision 可把 Run/Step 转入 RESUMING 并创建新 attempt，中间正向 decision 继续等待，reject/expire 进入唯一 finalizer。HumanGate、checkpoint、Run/mutation 幂等键、resume mutation 与未决通知必须纳入活跃保留条件，不能被初始 24 小时时钟或 7/30/90 天通用清理提前停用/删除。

`workspaces.credits_balance` 是当前可用积分，`credits_reserved_balance` 是活跃 reservation 的已预留积分，`credits_balance_version` 是每次资金移动的单调版本。004 按阶段拆开角色：`ba_admission_executor` 仅调用绑定 `accepted_plan_hash` 的 `reserve_credits`；`ba_metering_executor` 仅调用绑定 producer Run/Attempt、活跃且未过期的非空 lease token、fencing token 与 Step/usage attribution hash 的 `settle_credits`；`ba_finalizer_executor` 仅调用同样绑定当前活跃 lease 与 finalizer attribution 的 `release_credits` 和唯一 `finalize_run`；`ba_reconciliation_executor` 只调用幂等 `reconcile_needs_attention_billing`。四者互不继承、无表 DML，普通 `ba_runtime` 对这些函数无 EXECUTE；对应 NOLOGIN owner 只持有函数需要的列权限。它们不能执行外部 `authenticate_api_credential`，只能以绑定 workspace/session user/exact phase 的短期 internal service attestation 建立本事务 RLS context。资金函数固定以 Workspace 行锁 → billing-owner/producer Run/Attempt → reservation/allocation → `charge_key` 查重的顺序运行，且不自行提交事务。Gate reject/expire 等无 Worker lease 的入口必须先取得受控 finalizer claim，不能用空 lease 绕过。`release_credits(..., p_mark_expired=true)` 必须在同一锁定查询读回 reservation `expires_at`，当前时钟早于它时 fail-closed，不允许调用者提前标记过期并释放预留。`record_agent_charge` 以固定 `agent/v1/<billing-owner-run>/<metered-run>/<call-or-step>/<metering-unit>` 组成 charge key，先验证 attribution 的复合 FK 与 allocation 剩余额度，再把唯一的 SETTLE 写入 billing owner reservation/ledger 和 attribution；重复相同 key 只回读同一结算，绝不再次扣费。顶层 Run 准入才创建 Workspace reservation；异步 child Run 必须由后续原子 `allocate_child_budget` migration 从**根 billing-owner reservation** 的未用额度划拨，当前基线一律拒绝 child。finalizer executor 在同一外层事务先释放未用预留，再调用 `finalize_run` 收敛 Step、追加唯一 terminal Event、冻结 Run snapshot/墓碑和写 Outbox；join child 处于 `NEEDS_ATTENTION` 时父 Run 必须传播相同 operator-hold 终态；余额与预留均有非负约束，不能由 ClickHouse、Redis 或 `run_logs` 反推。`NEEDS_ATTENTION -> SETTLED` 对账必须原子写不可变 evidence、RECONCILIATION ledger、余额/reservation/current billing state 与 SSE wake，且不得改写终态。

当前 004 基线不开放任何 parent link；未来 G1 专属 migration 的数据库 CHECK 只允许 `completion_policy=join + cancel_propagation=cascade + result_projection=safe_summary + parent_terminal_policy=wait_for_settlement`，且必须把 child/link/allocation/event/outbox 与父 cancel cascade intents 原子化。届时父 Run 只能在所有 join child 终态且其 allocation 已结算/释放后进入业务终态；child 的 `accepted`、`terminal` 和安全结果摘要以父 Run Event/兼容 task 投影。当前及 G1 schema 都不保留 detach/do_not_cancel/none/structured/billing_pending link 值；G2 若需要必须新建 schema version、迁移与 sealed gate。未知/不可取消副作用按 ADR-004 进入共享 terminal NEEDS_ATTENTION。

`run_events` 与 `credits_ledger` 对 `ba_runtime` 不提供原始 event `INSERT/UPDATE/DELETE` 或账务写权限；runtime 的进度事件函数还必须绑定有效 attempt、lease token 与 fencing token，准入/租约/terminal/credit 事件走各自受控路径。Run event sequence 由锁定 Run 行的 trigger 分配；`runs.last_event_sequence + terminal_event_id + terminal_event_sequence` 在 event retention 后仍存续，使同 terminal intent 可从 Run 墓碑重放。到期清理由独立 `ba_retention` SECURITY DEFINER procedure 处理：EVENTS purge 只等待独立的 `events_retention_until`（G1 下界为终态后 7 天）并仅删事件；RECOVERY purge 才等待 `recovery_retention_until`（下界 30 天）与更长 `retention_until` policy horizon，并删除 checkpoint/已完成 outbox 等恢复材料。两类 purge 都要求 `billing_state=SETTLED`，NEEDS_ATTENTION 必须已有 reconciliation evidence。调用者不得在 purge 函数内自行插入 archive ref/hash 作为证据：函数必须读取并精确匹配一条**事先存在、不可修改、已验证且已审批**的 archive manifest 及 verification/approval receipt，ref/hash 不同立即失败；清理完成后按 `EVENTS|RECOVERY` 另追加 immutable purge receipt。`ba_archive_evidence_executor` 只能调用独立 owner 的 manifest registration 函数，无表 DML 和 purge EXECUTE；`ba_retention_executor` 只有 purge EXECUTE，无 manifest 表权限或 registration EXECUTE，其 NOLOGIN owner `ba_retention` 只有 manifest SELECT。两组角色不得互相继承。**G0/G1 禁止删除 `credits_ledger`**。未来财务清理必须另有独立 financial-retention policy、不可伪造外部归档回执、对账和双人审批，不能复用 `runs.retention_until`。所有低权可调用的 definer function 必须把 `pg_temp` 显式置于固定 `search_path` 末位并 schema-qualify 持久 relation。

Agent 公开入口创建 root Run 时，必须在同一准入事务从稳定 Deployment 的 active pointer 解析 revision，并关联同 Workspace、由该 revision 精确装配的 `deployment_revision_id + agent_release_id + experience_release_id`；未激活 revision 只能经显式内部 preview/test 路径进入隔离 Run。Run target registry 验证实际 Agent Release，`ResolvedAgentPlan` 另保存 compiled/dependency hash、Strategy/Instruction Skill pins、实解析 Capability/Knowledge generation pins、credential binding/Authorization Decision 摘要、模型策略、预算和强制调用顺序。直接 Flow/System Run 保持其判别 target pin，不得伪造 Agent Plan。`agent_instruction_skill_activations` 与 `agent_capability_calls` 分开记录；输入/输出只保存受分类与脱敏约束的摘要或受控对象引用，原始权限 SPI 响应、secret、完整数据库行和模型上下文不得进入事实表。

`run_logs` 只能是由 `run_events` / `agent_capability_calls` 投影出的兼容读模型。Postgres 是运行和账务事实源；ClickHouse 是可重建分析投影，Redis 是可重建队列/缓存，均不参与最终扣费判定。

后续专属 migration 启用 child 后，Run parent link 的单父约束仍不足以防止递归环。唯一受控的 `allocate_child_budget` 事务必须先按全局顺序锁住 Workspace、root billing owner、再按 UUID 升序锁住参与的 parent/child Run 和 reservation/allocation；随后用递归查询从候选 parent 沿既有 parent link 向上遍历，若遇到候选 child（含自环）即拒绝，且不写 allocation、event 或 outbox。它还验证 parent/child 都继承同一 top-level root owner；只允许该受控事务同时插入 child、link、allocation 与初始投递。应用角色不得原始写入 link/allocation，避免绕过递归检查或把持久化顺序拆开。

Run 进入终态时，唯一 `app.finalize_run` 必须重验证 current Attempt/活跃非空 lease/fence、join child、reservation、准入冻结的 accepted output schema ref+hash 与 termination-reason 映射，在同一事务把剩余 QUEUED Step 置为 SKIPPED、活动 Step 按原因置为 SUCCEEDED/FAILED/CANCELLED/NEEDS_ATTENTION，再一次写定 `termination_reason`、互斥的 `terminal_result_redacted|terminal_error_redacted`、`terminal_billing_pending`、`terminal_billing_pending_at`、`finished_at`、唯一 RUN_FINISHED、terminal event id/sequence 墓碑与 SSE outbox。成功结果必须由可信 registry-backed validator 按冻结 ref+hash 验证；只检查 JSON object 不够，当前 004 的显式 stub 在真实 validator migration 前拒绝 `SUCCEEDED`。非成功错误不由调用者自报，finalizer 从冻结的 termination reason 生成 closed `ErrorDetail`。这样 GET/cancel/finalizer replay 在 Event retention 后仍从 Run 快照与墓碑返回同一终态，而不是依赖已删除事件或重算模型/工具输出。`SIDE_EFFECT_UNKNOWN` 只能映射内部 terminal NEEDS_ATTENTION 并令 current billing state 初始为 NEEDS_ATTENTION；G1 历史 `terminal_billing_pending` 仍固定 false，公开 GET/blocking/SSE 映射为 `FAILED + SIDE_EFFECT_UNKNOWN + requires_operator_action`。004 基线因尚无可验证的 GateSpec disposition 关系而拒绝 `HUMAN_REJECTED|HUMAN_GATE_EXPIRED`；后续 Gate migration 必须以 gate/release 复合 FK 读取已发布 `on_reject|on_expire`，再按 disposition 映射 FAILED/CANCELLED，且未知副作用优先。快照一经写入不可修改；独立 `billing_state` 是当前结算投影，只可由受控 metering/finalizer/reconciliation 路径在 reservation/allocation 收敛或对账后更新，不能恢复或改写原 Run。

### 10.4 检索、对象与保留期

- `kb_embeddings` 用 embedding profile + dimension 隔离模型版本。切换模型必须双写/重嵌入并验证索引后切读，不能混用固定维度。
- 对象存储保存原始文件、大输入、大输出和模型片段；数据库保存对象 key、内容 hash、数据分类、workspace、版本和保留期。
- 运行事件、消息、session、对象、分析投影分别定义保留、删除、导出和 legal-hold 规则。`events_retention_until` 不早于终态 `finished_at + 7 days`，单独控制有限 SSE 事件窗口；`recovery_retention_until` 不早于 `finished_at + 30 days`，控制 checkpoint/已完成 outbox 等恢复材料；`retention_until` 承载更长合同/policy horizon。三个 horizon 均只能单调延长，且 `recovery_retention_until >= events_retention_until`、`retention_until >= recovery_retention_until`；EVENTS purge 仍只读取事件自己的 horizon，RECOVERY purge 才同时读取 recovery 与 policy horizon。活跃运行、长期 WAITING 的 Run/mutation 幂等键、`billing_state <> SETTLED`、未完成 outbox 和可恢复 checkpoint 一律不可清理；NEEDS_ATTENTION 还须有 immutable reconciliation evidence。终态技术材料清理只能消费独立归档管道事先写入的 immutable verified+approved manifest/receipt，精确 ref/hash 不匹配、manifest 不存在或同 material kind 已有 purge receipt均 fail-closed。event purge 后 Run 的 last cursor 与 terminal event 墓碑仍持久存在。

### 10.5 迁移验收

每次 migration 必须至少给出：

1. 表、索引、复合外键、RLS policy、全局表豁免和 secret 字段的 before/after 清单；
2. 同一业务资源的跨 Workspace 读、写、关联、后台重试、搜索投影、对象读写均被拒绝的测试；
3. pre-RLS 凭据/browser session 认证投影：`ba_runtime`/`ba_control_executor`/admission+metering+finalizer+reconciliation executors/app 对 `api_credentials` 的 `SELECT *` 与 verifier 列读取失败，安全列显式查询成功，私有 auth projection 无表直读且认证函数只返回三列；overlap 缺 rotation group/期限、超过服务端 24h 上限、延长到期或回 active 均失败，revoked/expired 永不回活；部署读回 DB/pooler/APM parameter never-log 配置，canary verifier 在成功/错误长度/首字节/末字节/异常路径的所有日志与导出零命中，部署函数定义仍只用 `constant_time_equal_32` 且 timing distribution 通过冻结阈值；伪造 `user.id` 无效、origin/audience/session epoch 校验、撤销立即失效、context 不可跨 session/事务复用。阶段 executor 只能用绑定 workspace/session user/exact phase 的最长 15 分钟 internal service attestation，任意外部 credential、wrong-phase、过期/撤销与跨事务 proof 均无 context；所有低权 SECURITY DEFINER 还须通过恶意临时同名表遮蔽测试；
4. registry / Run pin 的跨 Workspace/错误 kind 拒绝、promotion/rollback 不使旧 Run 漂移、会话 contract 不兼容在副作用前拒绝、Deployment revoke 只收窄；Run 接受 identity 任一列 UPDATE 失败，长期 WAITING Run/mutation key 不停用，非终态 expiry 失败，终态后保留至少 24h，canonical 202 receipt 重放；cancel hash 只由可信固定 JCS 函数生成且 mutation key 即使携带相同伪造 hash跨 target 也冲突；
5. 并发 reserve/settle/release、余额非负、accepted Plan/producer Run/Attempt/lease/fence/charge attribution 任一错配先于资金移动失败、`p_mark_expired=true` 在 reservation `expires_at` 前失败、同 charge_key 不同 `billing_intent_hash` 冲突、账本不可由 retention 删除；`ba_runtime` 与错误阶段 executor 调用资金/finalizer/reconciliation 函数 permission denied。`finalize_run` 对错误 reason/status、旧 fence、HELD reservation、未结算 join child、output schema ref/hash 不可信或验证失败均拒绝；当前 validator stub 必须拒绝 SUCCEEDED，真实 validator 启用后成功事务才有一个 terminal snapshot/Event/墓碑/Outbox，且 event purge 后相同 terminal intent 仍重放。相同 reconciliation key+intent 只写一次 evidence/RECONCILIATION ledger/状态推进且不改终态，不同 intent 冲突。purge 对缺失 manifest、不匹配 ref/hash、未验证/未审批证据、未 SETTLED billing、NEEDS_ATTENTION 缺 reconciliation evidence 和同 material kind 重复均拒绝；EVENTS/RECOVERY 分别验证 7/30 天窗口并追加各自 receipt；唯一取消/terminal 事件、有效 lease/fence 才能追加 runtime event、单调 cursor、event retention 后 GET/410 读回；
6. Agent Release 发布检查：编辑 Draft、升级 KB/Plugin/`skill_pack`/Flow 或变更 A2A endpoint 不改变既有 Release；Binding 类型、资源 pin、schema hash、workspace、数据分类、预算和 secret 污点全部被验证；数据库 catalog 证明 G0/G1 根本没有 floating/compatibility approval/audit 表列或 source kind，发布器也不接受这些输入；
7. Agent 授权与能力调用：subject kind、credential/service principal 复合 FK、Decision 完整 epoch source 集、scope/visibility/grant/policy/回调的 INSERT/UPDATE/revoke 与 durable invalidation 都被验证；撤销会原子递增权威 epoch 并阻止尚未开始或高风险 Call；Call、child Run、SSE/`tasks[]` 均可回读 release/pin/decision 的脱敏关联；
8. Agent Task/Mock/快捷入口：跨 Release Binding 引用、`task_safe=false`、非 Flow/Plugin Task、database/unsafe/non-`mock_safe` fixture、撤销服务主体和缺失三列复合 FK 都被 deferred trigger 拒绝；preview/batch 以外伪造 `simulation=true` 同样被拒绝；
9. 数据库 Binding：默认只读、参数/表/列/行策略、不可变 operation release/table revision、operation/release/table revision 跨数据库拼接、read/write access mode 不一致、最大行数、写入审批/operation key、未知副作用与数据库不可 Mock 均有集成夹具；
10. parent/child Run：当前基线对 child/link 与带 link cancel 全部 fail closed，不留下 allocation/event/outbox 半成品；后续专属 migration 必须以同一受控事务写 child/link/allocation/event/outbox、deferred exactly-one，并以可去重 cascade intents/outbox 传播父取消。该 migration 通过后 G1 才只接受 `join+cascade+safe_summary+wait_for_settlement`，证明 child 不二次预留/结算、allocation 不超额与 root → child → grandchild；detach/do_not_cancel/none/structured/billing_pending link 在 G1 catalog 不可写，未来仅在 G2 独立 migration+sealed gate 后解锁；
11. 空库 migrate、重复应用/forward-fix、备份恢复和 RLS policy 独立读回证据；生产不可变 Release/Run/ledger 不要求破坏性 down migration。
